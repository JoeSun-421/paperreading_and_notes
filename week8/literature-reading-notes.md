### 全文主线（滚动更新）

- **研究问题**：如何让视觉-语言-动作模型在没有见过的家庭环境中执行长时程、多阶段、灵巧的移动操作任务。
- **核心贡献**：提出 π0.5 的异质数据协同训练方案，并报告模型在全新真实家庭中执行厨房、卧室清理任务的结果。
- **方法主线**：先以离散 FAST 动作 token 对多机器人、语义子任务、网页视觉语言数据进行预训练；再以移动操作数据、语言示范等进行后训练，并用 flow matching 动作专家生成连续动作。推理时先预测语义子任务，再预测动作块。
- **关键结论**：论文的消融结果显示，跨本体机器人数据、跨环境数据、高层子任务数据、网页数据和人工语言示范对不同能力有不同贡献；论文报告 π0.5 在新家中完成若干分钟级任务。
- **主要限制**：仍会受陌生抽屉把手、遮挡、部分可观测性和高层策略分心影响；提示复杂度受训练标注约束，模型上下文与记忆有限。论文没有提供覆盖任意家庭和任意家务的保证。

###### 摘要

要让机器人真正有用，它们必须能在实验室之外的真实世界中执行实际相关的任务。视觉-语言-动作（VLA）模型在端到端机器人控制方面已展示出令人瞩目的结果，但这类模型在真实开放环境中的泛化能力究竟能达到什么程度，仍是一个开放问题。

我们介绍 π0.5：一个基于 π0 的新模型，通过在异质任务上协同训练来实现广泛泛化。π0.5 使用来自多种机器人的数据、高层语义预测、网页数据及其他来源，以支持具有广泛泛化能力的真实世界机器人操作。系统结合了协同训练与混合多模态样本；样本可同时包含图像观察、语言指令、物体检测、语义子任务预测和底层动作。实验表明，这种知识迁移对有效泛化至关重要。我们首次展示了一个端到端、由学习系统驱动的机器人系统，能够在完全陌生的家庭中执行长时程且需要灵巧操作的技能，例如清洁厨房或卧室。

###### I. 引言

“让你的眼睛充满惊奇……去看世界。它比工厂里制造或付费买来的任何梦境都更加奇妙。”——雷·布拉德伯里，《华氏 451》

开放世界泛化是具身智能领域最重要的开放问题之一。机械臂、人形机器人和自动驾驶汽车等具身系统，只有离开实验室并应对真实世界中多样的情况与意外事件，才真正有用。基于学习的系统为实现广泛泛化提供了一条路径，特别是自然语言处理 [79, 21, 10, 78] 和计算机视觉 [34, 66, 35, 43] 领域近期的进展，已经支持了可扩展的学习系统。然而，机器人在真实世界可能遇到的情况非常多样；仅仅扩大规模还不够。我们需要设计训练方案，为机器人提供足够广泛的知识，使其能在多个抽象层次上泛化。

例如，若让移动机器人清理一间从未见过的厨房，某些行为只要在足够多样的场景和物体中得到充分表示，就比较容易泛化，例如拿起刀或盘子。另一些行为则要求机器人调整或改造已有技能，以便在新用法或新顺序中使用。还有一些行为要求机器人利用先验知识理解场景语义，例如判断应该打开哪个抽屉，或台面上的哪个物体最可能是沥水架。我们该如何设计机器人学习系统的训练方案，使其能够灵活地实现这类泛化？

人可以调用一生积累的经验，为这些挑战综合出恰当的解决方案。这些经验不全来自亲身经历，也不全来自机械重复练习。比如，我们可以结合别人告诉我们的事实或书本中读到的内容、在其他情境中完成任务得到的启发，以及目标领域中的直接经验。类似地，我们可以假设，具备泛化能力的机器人学习系统也必须能够从多种信息来源迁移经验和知识。有些来源是与当前任务直接相关的第一手经验；有些需要从其他机器人本体、环境或领域迁移；还有些来自完全不同的数据类型，例如口头指令、基于网页数据的感知任务，或高层语义指令预测。不同来源之间的异质性构成重大障碍。幸运的是，近期 VLA 模型的发展提供了实现这一点的工具：把不同模态放进同一序列建模框架后，VLA 就可以在机器人数据、语言数据、计算机视觉任务及其组合上训练。

本文利用这一点，设计一个能使用多样异质知识来源的 VLA 协同训练框架，以实现广泛泛化。我们在图 1 中展示这一设计。机器人操作员可以像指导人一样，一步一步用语言带领机器人完成复杂任务，并告诉它应该执行哪些子任务，例如清理房间。

我们的核心贡献是提出训练高泛化 VLA π0.5 的系统，并提供概念验证：在适当多样的数据上训练后，该模型可以表现出泛化能力。我们详细评估 π0.5 的泛化能力，以及不同协同训练成分的作用。据我们所知，这是首个展示端到端学习机器人系统能在完全陌生的家中执行长时程、灵巧操作技能（例如清理厨房或卧室）的工作。实验和比较还表明，这种能力来自对其他机器人、高层语义预测、人工指导的口头语言、网页数据等知识的迁移。

**图 2 图注**：π0.5 在一个新厨房中进行清理。机器人被要求清理训练数据中未出现的家庭厨房。模型接收一般性任务（“关上橱柜”“把物品放进抽屉”“擦掉洒出的液体”“把餐具放进水槽”），然后通过预测要完成的子任务（例如“拿起盘子”）并输出底层动作来执行。

###### II. 相关工作

**通用机器人操作策略。** 近期研究表明，把机器人操作策略的训练分布从单一任务的小数据集扩展到涵盖多种场景和任务的数据集 [17, 25, 80, 63, 41, 6, 30, 67, 1]，不仅能让策略开箱即用地解决更多任务，也能提升它们对新场景和新任务的泛化能力 [9, 63, 62, 22]。训练这种通用策略需要新的建模方法，以处理常常涵盖数百种任务和场景的数据规模与多样性。视觉-语言-动作模型（VLA）[23, 92, 42, 8, 83, 90, 55, 45, 3, 75, 64, 76, 84, 7, 37] 是一种有吸引力的方案：通过将预训练视觉-语言模型微调用于机器人控制，VLA 可以利用从网页规模预训练中获得的语义知识，并将其用于机器人问题。再结合 flow matching [8]、扩散模型 [55, 84, 52] 或先进动作分词方案 [64] 等表达能力强的动作解码机制，VLA 可以在真实世界中完成多种复杂操作任务。

不过，尽管 VLA 的语言跟随能力令人印象深刻，它们通常仍在与训练数据高度相似的环境中评估。一些研究指出，只要在更广的环境中采集机器人数据，拿物体或打开抽屉等简单技能就可能泛化 [14, 67, 28, 49, 64]。但对“清理厨房”这类复杂长时程任务，靠暴力扩充机器人数据来覆盖所有可能情形并不可行。我们的实验在训练未见过的新厨房和卧室中评估 π0.5，展示 VLA 不仅能依赖目标移动机器人平台的第一手经验，也能利用其他数据源来泛化到全新场景。

**非机器人数据的协同训练。** 过去一些工作尝试利用多样的非机器人数据来提升机器人策略泛化能力。已有方法包括用计算机视觉数据集初始化视觉编码器 [85, 58, 57, 18]，或利用现成任务规划器 [38, 48, 73, 81]。VLA 策略通常从接触过大量互联网视觉和语言数据的预训练视觉-语言模型初始化 [23, 92, 42]。VLA 架构很灵活，能在多模态视觉、语言和动作 token 的输入与输出序列间建立映射。因此，VLA 扩展了可迁移方法的设计空间：不只是权重初始化，也能让一个统一架构在不同数据集上协同训练，而这些数据集可以交错包含前述模态中的一种或多种。

已有研究表明，在 VLA 上协同训练 VLM 使用的数据混合 [23, 92, 86]，可以提升泛化能力，例如帮助模型与新物体交互，或适应未见过的场景背景。本文超越了仅与 VLM 数据协同训练的做法，设计了一个更广泛的方案，将机器人相关监督来源纳入 VLA 协同训练，包括其他机器人数据、高层语义子任务预测和口头语言指令。多任务训练和协同训练本身并不新颖；本文主张，正是特定数据源的组合，使移动机器人能在全新环境中执行复杂长时程行为。作者认为，若同时考虑任务复杂度，这种泛化程度明显超过此前工作展示的结果。

**使用语言进行机器人推理与规划。** 许多先前工作表明，在端到端策略中加入高层推理，可以显著提升长时程任务表现 [2, 36, 44, 74, 71, 4, 16, 11, 53, 88, 51, 59, 13, 70, 91, 65, 72, 47, 76, 89]；尤其当高层子任务推断可以利用预训练 LLM 和 VLM 时更是如此。本文方法也采用两阶段推理：先推断一个高层语义子任务（例如“拿起盘子”），再根据该子任务预测动作。许多先前方法使用两个独立模型：VLM 预测语义步骤，另一个低层策略执行步骤 [2, 71, 13, 24, 70, 72, 47]。本文使用同一个模型完成高层和低层推理，这更像思维链 [82] 或测试时计算 [39] 方法；不过，与具身思维链方法 [88, 46, 61] 不同的是，高层推理的运行频率仍低于低层动作推理。

**具有开放世界泛化能力的机器人学习系统。** 大多数机器人学习系统仍在与训练环境相近的场景中评估。部分工作探索了更广泛的开放世界泛化。如果任务限于少数基础技能，例如拿起物体，那么利用任务特定假设（如抓取预测，或结合基于模型的规划与控制）的方法，已经能够泛化到全新家庭 [40, 20, 60, 56, 29]。但这些方法难以自然地扩展到通用机器人可能需要执行的全部任务。近期，跨多个领域的大规模数据集 [41, 68, 63, 67, 14, 49] 已被证明可以帮助简单的端到端学习任务泛化到新环境 [33, 31, 67, 69, 26, 49, 28, 64]。然而，这些示范中的任务仍相对简单，通常不到一分钟，成功率也往往较低。本文展示 π0.5 可以在全新家庭环境中完成长、多阶段任务，例如把所有餐具放进水槽，或捡起新卧室地板上的所有衣物。

###### III. 预备知识

VLA 通常通过在多样化机器人示范数据集 $D$ 上进行模仿学习来训练，目标是最大化给定观察 $o_t$ 和自然语言任务指令 $\ell$ 时动作（或动作块）的对数似然：

$$
\max_\theta\;\mathbb{E}_{(a_{t:t+H},o_t,\ell)\sim D}\left[\log\pi_\theta(a_{t:t+H}\mid o_t,\ell)\right].
$$

观察通常包含一张或多张图像 $I_t^1,\ldots,I_t^n$，以及记录机器人关节位置等信息的本体感知状态 $q_t$。VLA 架构沿用现代语言模型和视觉-语言模型的设计：使用模态专属的 tokenizer，把输入输出映射为离散（“硬”）或连续（“软”）token 表示，再通过大型自回归 Transformer 把输入映射为输出。模型权重从预训练视觉-语言模型初始化。把策略输入和输出编码成 token 后，模仿学习就能转化为对观察、指令和动作 token 序列进行下一 token 预测，从而使用现代机器学习的可扩展优化工具。图像和文本输入的 tokenizer 通常沿用现代 VLM；动作方面，已有基于压缩的有效 tokenization 方法 [64]，本文在预训练阶段使用它。近期 VLA 模型也提出用扩散 [55, 84, 52] 或 flow matching [8] 表示连续动作块分布。本文后训练阶段采用 π0 [8] 的设计，用 flow matching 表示动作分布：动作 token 接收上一步 flow matching 产生的部分去噪动作，并输出 flow matching 向量场。动作 token 使用一套独立权重，称为“动作专家”，类似混合专家架构。动作专家可专门负责基于 flow matching 的动作生成，其规模可以显著小于 LLM 主干。

###### IV. π0.5 模型与训练方案

图 3 概述 π0.5 及其训练方案。模型权重从在网页数据上训练的标准 VLM 初始化，之后分为两阶段：预训练使模型适应多样的机器人任务；后训练使模型专门适配移动操作，并让测试时推理更高效。预训练中，包括机器人动作在内的所有任务都用离散 token 表示，因此训练简单、可扩展且高效 [64]。后训练加入类似 π0 的动作专家，以更细粒度地表达动作，并实现计算效率更高的实时推理。推理时，模型先为机器人生成一个高层子任务，再以该子任务为条件，通过动作专家预测低层动作。以下先介绍模型架构，再介绍各阶段及相应训练任务。

**图 3 图注**：π0.5 分两阶段训练。第一阶段预训练将不同数据源组合起来，得到一个使用离散 token 的初始 VLA；数据包括不同机器人平台、高层语义动作预测和网页数据，机器人动作使用 FAST tokenizer 离散化 [64]。第二阶段后训练利用最相关的数据（包括人工提供的口头指令）让模型专门适配移动操作的高层与低层推理。此阶段使用 flow matching 表示动作分布，以支持高效实时推理和细粒度连续动作序列。推理时模型先推断高层子任务，再根据子任务预测动作。

**A. π0.5 架构。** π0.5 能同时表示动作块分布和文本 token 输出。文本输出既用于协同训练任务（例如问答），也用于层级推理中的高层子任务预测。模型表示的分布写作

$$
\pi_\theta(a_{t:t+H},\hat\ell\mid o_t,\ell),
$$

其中 $o_t=[I_t^1,\ldots,I_t^n,q_t]$ 由所有相机图像和机器人配置（关节角、夹爪姿态、躯干升降位置、底盘速度）组成；$\ell$ 是整体任务提示（例如“收拾餐具”）；$\hat\ell$ 是模型生成的文本输出，可以是预测的高层子任务（例如“拿起盘子”），也可以是网页数据中的视觉语言问题答案；$a_{t:t+H}$ 是预测的动作块。分布被分解为

$$
\pi_\theta(a_{t:t+H},\hat\ell\mid o_t,\ell)
=\pi_\theta(a_{t:t+H}\mid o_t,\hat\ell)\,\pi_\theta(\hat\ell\mid o_t,\ell).
$$

因此，动作分布依赖 $\hat\ell$，而不直接依赖原始高层指令 $\ell$。高层推理建模 $\pi_\theta(\hat\ell\mid o_t,\ell)$，低层推理建模 $\pi_\theta(a_{t:t+H}\mid o_t,\hat\ell)$，两者由同一模型表示。

模型是一个 Transformer，接收 $N$ 个多模态输入 token $x_{1:N}$，输出多模态序列 $y_{1:N}$。这里的 token 一词同时指离散和连续输入。每个 $x_i$ 可以是文本 token $x_i^w\in\mathbb{N}$、图像块 $x_i^I\in\mathbb{R}^{p\times p\times3}$，或 flow matching 中机器人动作的中间去噪值 $x_i^a\in\mathbb{R}^d$。观察 $o_t$ 和指令 $\ell$ 构成输入前缀。不同类型 token 可经过不同编码器，也可在 Transformer 内使用不同专家权重：图像块经过视觉编码器，文本 token 经嵌入矩阵处理；遵循 π0 [8]，动作 token 线性投影到 Transformer 嵌入空间，并由独立专家权重处理。注意力矩阵 $A(x_{1:N})\in[0,1]^{N\times N}$ 表示 token 之间是否允许互相注意。

模型需要输出文本（回答场景问题或输出下一子任务）和动作，因此 $f$ 的输出分为文本 token logits 和动作输出 token。前 $M$ 个是文本 token logits，可用于采样 $\hat\ell$；后 $H$ 个由独立动作专家产生，并经线性映射得到连续动作 $a_{t:t+H}$。满足 $M+H\leq N$，因为并非所有输出都参与损失。机器人本体感知状态离散化后作为文本 token 输入。架构更多细节见附录 E。

**B. 离散与连续动作表示的结合。** 与 π0 类似，最终模型使用 flow matching [50] 预测连续动作。给定

$$
a_{t:t+H}^{\tau,\omega}=\tau a_{t:t+H}+(1-\tau)\omega,
\qquad \omega\sim\mathcal{N}(0,I),\quad \tau\in[0,1],
$$

模型训练目标是预测 flow 向量场 $\omega-a_{t:t+H}$。不过，已有研究 [64] 表明，尤其使用 FAST 这类能有效压缩动作块的 tokenizer 时，把动作表示成离散 token 可以大幅加快 VLA 训练。缺点是离散表示不太适合实时推理，因为需要昂贵的自回归解码。因此，理想设计应当既能用离散动作训练，又能在推理时通过 flow matching 生成连续动作。

为此，模型同时通过自回归采样 token（使用 FAST tokenizer）和对 flow 向量场进行迭代积分来预测动作，结合两种方式的优点。注意力矩阵确保两种动作表示不会互相注意。优化目标为

$$
\mathbb{E}_{D,\tau,\omega}\!\left[
H\!\left(x_{1:M},f^{\ell}_\theta(o_t,\ell)\right)
+\alpha\left\|\omega-a_{t:t+H}-f^{a}_\theta(a_{t:t+H}^{\tau,\omega},o_t,\ell)\right\|^2
\right],
\qquad\text{(1)}
$$

其中 $H(x_{1:M},y_{1:M}^{\ell})$ 是文本 token（包括 FAST 编码动作 token）的交叉熵损失；$y_{1:H}^{a}=f_\theta^a(a_{t:t+H}^{\tau,\omega},o_t,\ell)$ 是较小动作专家的输出；$\alpha\in\mathbb{R}$ 是权衡参数。这个方案使模型可以先作为标准 VLM 训练，将动作映射为文本 token（此时 $\alpha=0$），之后在后训练阶段加入额外动作专家权重，以非自回归方式预测连续动作，从而更快推理。作者报告，这一流程带来了稳定预训练和良好的语言跟随能力。推理时先对文本 token $\hat\ell$ 做标准自回归解码，再以文本 token 为条件执行 10 步去噪，生成动作块 $a_{t:t+H}$。

**图 4 图注与图中类别**：预训练样例包含实验室跨本体数据、不同环境中的移动操作机器人数据、高层子任务、口头指令、多样的非移动操作机器人数据和多模态网页数据。图中任务示例包括：整理抽屉、把衬衫放进篮子、把锅铲放入架子、擦盘子、搬到衣柜、拿起手套、铺床、把餐具放进水槽、叠衣服、公交车/餐桌（bussing a table）、把物品放进抽屉、叠床单、整理桌面、打开 X-Embodiment、橱柜收纳、把水壶放到底座、把毛巾挂到烤箱把手。网页示例包括图像描述、区域描述、视觉问答，以及将策略标签重标为“把盘子放在架子上”或“拿起蓝衬衫”。后训练使用口头指令，省略实验室跨本体数据，专注于移动操作和多样环境。图中展示的是各类别的一部分任务示例。

**C. 预训练。** 第一阶段中，π0.5 用广泛的机器人和非机器人数据训练，执行文本、物体位置和 FAST 动作 token 的自回归下一 token 预测（见图 4）。

- **多样移动操作机器人数据（MM）**：约 400 小时移动操作机器人在约 100 个不同家庭环境中执行家务的数据，使用 §IV-E 所述机器人。部分任务与评估直接相关，例如清理和整理。它是最直接相关于评估任务的数据切片。
- **多环境非移动机器人数据（ME）**：我们还收集了多种家庭环境中的非移动单臂或双臂机器人数据。机械臂固定在台面或安装平台上，因其更轻、更容易运输，能够在更多家庭采集数据。ME 数据来自不同于移动机器人的本体。
- **实验室跨本体数据（CE）**：在实验室里，使用多种机器人完成范围广泛的任务，例如收拾餐桌、叠衬衫。部分任务与本文评估直接相关（例如把餐具放进收纳箱），另一些则不相关（例如研磨咖啡豆）。数据包含单臂和双臂机械臂、固定底座和移动底座，并包括开源 OXE 数据集 [15]。它是 π0 [8] 所用数据集的扩展版本。
- **高层子任务预测（HL）**：把“清理卧室”这类高层任务分解成“整理毯子”“拿起枕头”等较短子任务，类似语言模型的思维链提示，有助于策略理解当前场景并判断下一步。对于 MM、ME、CE 中包含多个子任务的机器人数据，研究者人工标注语义子任务，并训练 π0.5 根据当前观察和高层指令同时预测子任务标签（文本）及以该标签为条件的动作。因此模型自然具备高层策略（输出子任务）和执行这些子任务的低层策略两种功能。研究者还标注当前观察中的相关边界框，并训练 π0.5 在预测子任务前先预测这些边界框。
- **多模态网页数据（WD）**：加入多种网页数据，包括图像描述（CapsFusion [87]、COCO [12]）、问答（Cambrian-7M [77]、PixMo [19]、VQAv2 [32]）和目标定位。对目标定位，研究者还扩展标准数据集，加入带边界框标注的室内场景和家居物体网页数据。

对所有动作数据，模型都训练为预测目标关节姿态和末端执行器姿态。为区分二者，研究者在文本提示中加入“`<control mode> joint/end effector <control mode>`”。所有动作均按各数据集中每个动作维度的 1% 与 99% 分位数归一化到 $[-1,1]$。动作 $a$ 的维度设为足以容纳所有数据集中最大动作空间的固定值；对于配置和动作空间较低维的机器人，动作向量以零填充。

**D. 后训练。** 使用离散 token 预训练 280k 个梯度步骤后，进行第二阶段训练，称为后训练。此阶段既让模型专门适应家庭移动操作，也加入可以通过 flow matching 生成连续动作块的动作专家。训练同时使用下一 token 预测（保留文本预测能力）和动作专家的 flow matching；动作专家在后训练开始时随机初始化。优化式 (1)，$\alpha=10.0$，再训练 80k 步。后训练动作数据使用 MM 和 ME 中成功且低于固定长度阈值的 episode。加入网页数据（WD）以保留语义与视觉能力；加入与多环境数据对应的 HL 部分。为提升高层子任务预测，研究者还收集口头指令示范（VI）：专家实时遥操作机器人，并用语言一步步指定适当子任务，机器人则由已训练的低层策略执行。这些“语言示范”为高层策略提供了示例。

**E. 机器人系统细节。** 图 5 展示移动操作实验所用机器人。实验使用两类移动操作平台，两者都配备两个 6 自由度机械臂、平行夹爪、腕部单目 RGB 相机、轮式全向底盘和躯干升降机构。底盘状态和动作包括二维线速度与一维角速度；躯干升降机构是一维（上下）或二维（上下及前后）。除两个腕部相机外，机器人还在双臂之间安装前向和后向相机。高层推理使用全部四台相机；低层推理使用腕部相机和前向相机。根据平台不同，状态和动作空间总维数为 18 或 19。

**图 5 图注**：机器人系统概览。使用两种移动操作平台；每台有四台相机（前、后、左右腕部）、两个 6 自由度机械臂和平行夹爪、移动底座及躯干升降机构。π0.5 控制两侧机械臂和夹爪的关节、底盘速度及升降位置，状态和动作空间为 18–19 个自由度。图中标注：4 台图像相机；2 个 6 DoF 机械臂与 1 DoF 夹爪；2 台腕部相机；1–2 DoF 升降机构；3 DoF 全向底盘。

控制系统很简单：π0.5 以 50 Hz 直接下发机械臂、夹爪、躯干升降位置的目标姿态，以及底盘目标速度，并使用动作块。简单 PD 控制器跟踪这些目标，没有额外轨迹规划或碰撞检测。所有操作和导航控制均为端到端。

###### V. 实验评估

π0.5 的目标是在新环境中广泛泛化。与常在训练环境相近场景评估 VLA 的做法不同，本文所有实验都在训练时未见的环境中进行。定量比较使用可控、可复现的模拟家庭场景；最真实的最终评估在三个不属于训练集的真实家庭中进行（图 6）。实验研究五个问题：1）π0.5 能否泛化到全新家庭中的复杂多阶段任务？2）泛化能力如何随训练数据中的不同环境数量变化？3）各协同训练成分有何贡献？4）π0.5 与 π0 相比如何？5）高层推理有多重要，与直接低层推理及 oracle 高层基线相比如何？

**图 6 图注**：评估环境。我们在训练中未见的全新厨房和卧室评估 π0.5，其中物体、背景和布局均新颖。左侧的模拟房间用于可控、可复现的定量比较；右侧的真实家庭用于更贴近现实的最终评估。

**A. π0.5 能否泛化到真实家庭？** 为回答问题（1），研究者用两种机器人类型，在训练数据中未出现的三个真实家庭评估 π0.5。每个家庭都让机器人完成卧室和厨房清理任务。附录 B 给出评分标准，大致对应任务步骤完成的百分比（例如把一半餐具放进水槽约得 50%）。图 7 显示，π0.5 能在每个家庭中稳定完成多种任务；模型还能做更多定量评估之外的任务。许多任务包含多个阶段（例如移动多个物体），持续约 2–5 分钟。机器人只收到简单高层指令，例如“把餐具放进水槽”，高层推理会自主决定步骤，例如“拿起杯子”。作者认为，就环境新颖程度、任务持续时间和复杂度而言，这一真实环境泛化超出此前 VLA 的展示结果。

**图 7 图中示例与图注**：真实家庭中的示例 rollout。Home 1：人类指令“把物品放进抽屉”；模型依次预测“拉开抽屉”“拉开右侧顶部抽屉”“拿起钳子”“把钳子放入抽屉”“推上顶部抽屉”。Home 2：指令“把餐具放入水槽”；预测“拿起盘子”“把盘子放进水槽”“把杯子放进水槽”“拿起勺子”“拿起碗”。Home 3：指令“把衣物放进洗衣篮”；预测“拿起衬衫”“拿起衬衫”“把衣物放进洗衣篮”“把衬衫放进洗衣篮”“把衣物放进洗衣篮”。图注：我们在训练未见过的三个真实家庭的厨房和卧室评估 π0.5，任务包括“抽屉收纳”“洗衣篮”“餐具放入水槽”，结果显示 π0.5 能在这些全新真实家庭中成功完成任务。图 7(b) 将每个任务的进度按环境对 10 次试验取平均，并显示模拟评估设置的表现能够代表真实家庭表现。

**B. 泛化如何随场景数量变化？** 研究者改变移动操作数据中的环境数量（3、12、22、53、82、104 个地点），观察其对泛化的影响。由于对每个数据集都完整执行预训练和后训练的成本过高，实验先在不含移动操作数据的机器人动作预测混合数据上预训练，再比较使用不同数量环境的移动操作数据进行后训练的模型。尽管按地点划分的数据集规模理论上不同，但每种模型都训练 40k 步，使其看到相同数量的独立样本，从而控制后训练中环境数量实验的数据规模。

每个模型都在图 6 的模拟环境评估，这些环境未用于训练。评估分两类：第一，使用附录 B 的标准评分，在模拟测试家庭评估端到端多阶段任务，包括餐具入水槽、物品入抽屉、收拾衣物和整理床铺；第二，评估语言指令跟随和与新物体交互的细粒度能力，要求机器人根据语言指令从厨房台面拾取指定物体。物体包括训练中见过类别的新实例，以及训练未见类别的分布外物体；后者需要广泛语义泛化。

图 8 的结果表明，平均任务表现通常随训练地点增加而提升。为了衡量最终模型（104 个训练地点）弥合了多少泛化差距，研究者加入一个直接在测试家庭数据上训练的对照（绿色）。该对照与 104 地点模型性能相近，说明协同训练方案让模型达到接近见过测试家庭数据的表现。为了确认这一结果依赖完整协同训练方案，研究者还加入两个没有预训练协同任务的基线：一个直接使用测试环境数据训练（浅绿色），另一个只用 104 个训练地点的移动操作数据训练（浅黄色）。两者表现显著较差，说明其他协同训练数据源对泛化很重要，即使策略见过测试家庭机器人数据也是如此。若没有测试家庭数据，完整预训练方案尤其重要，绿色柱与浅黄色柱之间差距很大。

第二项语言跟随实验见图 9。语言跟随率衡量机器人是否选对指令中的物体；任务成功率衡量机器人是否把物体成功放入正确位置（抽屉或水槽）。研究者分别测量训练中见过的物体类别（新实例）和未见类别（分布外物体）。随着训练地点数量增加，语言跟随率和任务成功率均提升。符合预期，训练内物体类别的表现提升更快；每个新环境带来新的家居物品，使模型整体更稳健，并开始泛化到训练中没有出现的任务类别。

**图 8 图注**：地点数量对性能的影响。四个测试任务（餐具入水槽、物品入抽屉、洗衣篮、整理床铺）的表现随训练环境数量增加而改善。虚线绿线和绿色柱表示训练数据包含测试家庭的基线；最佳模型虽然没见过测试家庭数据，表现仍与其相近。

**图 9 图注**：不同训练地点数下的语言跟随评估。测量机器人按用户指示拾取物品并将其放入抽屉或水槽的语言跟随率与成功率，分别对训练见过类别（分布内）和未见类别（分布外）求平均。性能随训练地点数稳步提高。

**C. 协同训练方案的各部分有多重要？** 为回答问题（3），研究者将完整 π0.5 与其他训练数据混合方案比较，使用模拟家庭端到端任务表现和 §V-B 的语言跟随评估。完整方案使用多环境移动机器人数据（MM）、多环境静态操作机器人数据（ME）、实验室跨本体数据（CE）、高层语言子任务预测数据（HL）和网页数据（WD）。后训练还使用口头指令数据（VI），其作用在 §V-E 分析。消融包括：1）去掉 WD；2）去掉 ME；3）去掉 CE；4）同时去掉 ME 和 CE，即只用目标移动机器人平台数据与网页数据训练。

模拟家庭任务结果见图 10，逐任务结果见附录 D。去掉 ME 或 CE 任意一类跨本体数据都会显著降低表现，说明 π0.5 从其他环境（ME）及其他任务（CE）的跨本体迁移中受益；两者都去掉时损害更严重。有趣的是，此实验中去掉 WD 后的性能差异没有统计显著性，但后文表明网页数据对语言跟随和高层推理有很大影响。

图 11 的语言跟随结果趋势相似：去掉 ME 和/或 CE 会显著降低表现。不同之处在于，去掉网页数据会显著降低分布外物体表现。作者推测，网页数据包含广泛物体知识，可帮助模型理解并遵循涉及训练未见物体类别的语言指令。

**图 10 图注**：模拟家庭中的训练方案消融。对四个测试任务的每种模型变体进行评估（每个策略和任务 10 次试验）。加入多样环境中的跨本体数据（ME）和实验室跨本体数据（CE）都很重要；去掉其中任意一种或两者都会导致显著退化。WD 在这些实验中的影响不显著，但图 11 和 13 显示它会影响物体泛化和高层性能。

**图 11 图注**：训练方案消融的语言跟随结果。比较不同地点数量训练后，模型对分布内和分布外物体的语言跟随能力。WD 尤其对分布外物体表现重要；CE 和 ME 对分布内外表现都有较大影响。

**D. π0.5 与其他 VLA 相比如何？** 研究者将 π0.5 与原始 π0 VLA 以及改进版 π0-FAST+Flow 比较。后者按照式 (1) 联合训练扩散和 FAST 动作预测，但只使用动作数据，不含 HL 或 WD。它们是有力基线，因为 π0 已展示出复杂、灵巧移动操作能力，而 π0-FAST+Flow 尽可能接近 π0.5。为公平比较，所有模型使用相同的跨本体机器人训练集，并训练相近步数。不同点在于：（1）π0.5 还使用 HL 和 WD 数据；（2）π0.5 采用混合训练流程：预训练阶段使用离散 token，后训练阶段才用 flow matching 动作专家；π0 始终使用动作专家。π0-FAST+Flow 沿用混合流程，但只使用含机器人动作的数据，因此不能执行高层推理。

图 12 显示，π0.5 显著优于 π0 和 π0-FAST+Flow。即使允许 π0 训练更久，最多 300k 步，结果仍成立。这也验证了 Pertsch 等人 [64] 的发现：与纯扩散训练相比，FAST token 训练在计算效率方面更好。

**图 12 图注**：π0.5 与其他模型的比较。完整模型在模拟家庭测试环境中显著优于 π0 和 π0-FAST+Flow。

**E. 高层推理有多重要？** 高层推理机制接收“清理卧室”等高层指令，输出“拿起枕头”等子任务，再把子任务作为上下文交给低层系统预测动作，类似思维链推理 [82]。尽管 π0.5 使用一个统一架构执行高层和低层推理，也可以构造其他基线：完全省去高层推理，直接把任务提示输入低层系统（这是标准 VLA 常见做法 [92, 8]）；或者换用其他模型进行高层推理。所有基线都使用 π0.5 的完整低层推理，仅更换高层策略：

1. **π0.5**：模型同时执行高层和低层推理。
2. **no WD**：去掉网页数据的 π0.5 消融。
3. **no VI**：去掉口头指令数据的 π0.5 消融。
4. **implicit HL**：运行时不做高层推理，但训练时保留高层数据，可能让模型隐式学会子任务知识。
5. **no HL**：运行时不做高层推理，训练中也完全去掉高层数据。
6. **GPT-4**：用 GPT-4 作为高层策略，提示中提供任务描述和常用标签列表，以适配领域；此消融测试高层策略在机器人数据上训练的重要性。
7. **human HL**：由专家人类充当高层 oracle 策略，作为性能上界。

结果见图 13。完整 π0.5 表现最好，甚至超过 human HL oracle。令人意外的是，第二好的是 implicit HL：运行时不显式做高层推理，但训练时仍使用完整数据混合，包括子任务预测。这强烈说明协同训练数据方案本身很重要：显式推断高层子任务有额外好处，但仅在训练混合中加入子任务预测数据，已经能获得其中很大一部分收益。训练中连 HL 数据都去掉的 no HL 明显更差。结果还表明，规模相对较小的口头指令数据也很关键：它只占高层移动操作示例的约 11%，但 no VI 显著较弱。no WD 也显著更差；网页数据的相当一部分收益（这并不意外）体现在改善高层策略。

**图 13 图注**：高层推理流程评估。完整 π0.5（高层和低层推理）表现最好。不显式高层推理、但训练包含高层样本的 implicit HL 也受益于高层子任务数据。去掉口头指令（no VI）或网页数据（no WD）会显著退化；零样本提示大型 API 模型 GPT-4 的表现更差。

###### VI. 讨论与未来工作

本文介绍 π0.5：一个基于 π0、通过协同训练融合多种数据源并实现新环境泛化的模型。π0.5 能控制移动操作机器人，在训练未见过的家庭里清理厨房和卧室、整理床铺、挂毛巾，并执行其他多阶段、灵巧行为。π0.5 使用约 400 小时移动操作数据，但同时利用了更多其他机器人数据，包括多样环境中的非移动操作机器人数据和实验室数据；模型还与网页数据和根据机器人观察预测语言指令的高层数据联合训练。π0.5 的泛化能力显示，这种协同训练方案有助于有效迁移：仅使用中等规模的移动操作数据集，也能实现高度泛化的移动机器人控制。

π0.5 仍有局限。尽管泛化广泛，模型仍会犯错。有些环境持续带来困难，例如不熟悉的抽屉把手，或机器人难以打开的橱柜；部分可观测性也会造成困难，例如机器人手臂挡住需要擦掉的液体；有时高层子任务推断容易分心，例如收纳物品时反复开关抽屉。未来可以通过更好的协同训练、迁移和更大数据集改善这些问题。

其他未来方向可以处理方法的技术限制。π0.5 能执行多种厨房和卧室清理行为，但目前处理的提示相对简单。模型能处理多复杂的提示，取决于训练数据；可以通过人工标注或合成方式生成更细致、更多样的标注，从而加入更复杂的偏好与指令。模型上下文也相对有限；加入更丰富的上下文和记忆，可能显著增强模型在部分可观测场景下的能力，例如需要在不同房间之间导航，或记住物品存放位置的任务。更广泛地说，π0.5 探索了特定的异质数据源组合，未来仍可探索更多来源。例如，系统从口头指令学习的能力提供了一种有力的新监督方式，未来可以继续研究人们如何向机器人提供额外上下文知识。作者希望本文能成为新一代 VLA 的基础，使其在多样真实环境中具备广泛泛化能力。

###### 附录 E：模型技术细节

π0.5 基于 π0，采用 PaliGemma VLM [5] 作为视觉语言理解主干，并配有用于快速动作生成的“动作专家”。VLM 主干接收图像序列 $[I_t^1,\ldots,I_t^n]$、语言提示 $\ell$，以及 π0 中使用的机器人本体感知状态 $q_t$（token 化后）和动作 token [64]（由自回归方式预测）。动作专家是较小的 Transformer，接收动作时域为 50 的一段带噪动作 token $a_{t:t+H}^{\tau,\omega}$，即 $H=49$，并通过 flow matching 目标训练。

带噪动作块（动作维度 $d$）先经单个线性层投影到 Transformer 嵌入维度。与 π0 将 flow matching 时间步 $\tau$ 和带噪动作融合后输入 Transformer 不同，π0.5 用单独的 MLP 投影 $\tau$，再用自适应 RMSNorm 将时间步信息注入动作专家的每一层。时间步 MLP 为

$$
\operatorname{swish}\!\left(W_2\,\operatorname{swish}\!\left(W_1\,\phi(\tau)\right)\right),
$$

其中 $\phi:\mathbb{R}\to\mathbb{R}^w$ 是正弦位置编码函数 [79]，$W_1,W_2\in\mathbb{R}^{w\times w}$。动作专家输出 $y_{1:H}^{a}$，再通过最终线性投影解码为目标向量场。

两个 Transformer 的维度沿用 π0。由 PaliGemma 权重初始化的 2B VLM：宽度 2048、深度 18、MLP 维度 16,384、18 个注意力头、1 个 KV 头、头维度 256。300M 参数动作专家使用相同的深度、注意力头数、KV 头数和头维度，但宽度为 1024、MLP 维度为 4096。

VLM 与动作专家的嵌入只通过自注意力交互。图像、提示 token 和本体感知状态使用完整前缀 mask；FAST 动作 token 可以注意前缀和此前的自回归动作 token。动作专家嵌入可以注意前缀和彼此，但不能注意 FAST 动作 token，以避免两种动作表示之间的信息泄漏。信息实际上只从 VLM 单向流向动作专家，VLM 嵌入不会注意动作专家。图 18 展示各层注意力掩码示例。

**图 18 图注**：π0.5 注意力掩码模式示例。VLM 与动作专家的嵌入仅通过自注意力交互；前缀（图像、提示、本体感知状态）使用完整前缀掩码；FAST 动作 token 注意前缀及先前 FAST token；动作专家 token 注意前缀及其他动作专家 token，但不注意 FAST 动作 token，从而避免动作表示间的信息泄漏。信息只从 VLM 流向动作专家，不会反向流动。

flow matching 时间步 $\tau$ 的采样遵循 π0。它不采用标准均匀分布 $\tau\sim U(0,1)$ [50, 54]，也不采用强调中段时间步的方法 [27]，而是采用强调较低时间步的分布 [8]：

$$
p(\tau)=\operatorname{Beta}\left(\frac{s-\tau}{s};\alpha=1.5,\beta=1\right).
$$

当积分步长 $\delta$ 满足 $\delta>1-s$ 时，超过阈值 $s$ 的时间步不会被采样，因为它们不需要。实验中设 $s=0.999$，最多支持 1,000 个积分步（$\delta>0.001$）。

所有输入图像都进行图像增强，顺序为随机裁剪、缩放、旋转和颜色抖动，超参数如下：

```python
transforms = [
    augmax.RandomCrop(int(width * 0.95), int(height * 0.95)),
    augmax.Resize(width, height),
    augmax.Rotate((-5, 5)),
    augmax.ColorJitter(
        brightness=0.3,
        contrast=0.4,
        saturation=0.5,
    ),
]
```

##### 详细解释：方法、公式与实验如何连起来

###### 1. 这篇文章要解决的泛化是哪几层

论文里的“新环境泛化”不只是背景换了颜色。长任务至少包含三类难点：

1. **感知与类别迁移**：看到训练中没出现过的厨房布局、物品实例甚至物体类别，仍能识别“要拿的是剪刀”或“这是衣物”。
2. **动作技能迁移**：把别的机器人或别的场景中学到的抓取、开抽屉、放置动作迁移到当前移动底盘和机械臂。
3. **任务组合与语义推断**：收到“清理厨房”后，决定接下来应执行什么子任务，以及如何排列多步操作。

只扩大目标机器人示范，可能让常见单步技能变好，却很难覆盖家庭中的所有布局、物品与任务顺序。因此论文把问题转为：不同数据源分别教模型什么，能否让一个模型共同吸收这些知识。

###### 2. 数据来源与能力对应

| 数据 | 训练内容 | 主要提供的能力（作者解释及合理对应） |
|---|---|---|
| MM：移动操作，多家庭约 400 小时 | 与目标平台接近的家务动作 | 目标机器人上的直接技能和环境经验 |
| ME：非移动机械臂，多家庭 | 其他本体在真实家居环境操作 | 跨环境、物体和本体的操作经验 |
| CE：实验室跨本体、多任务 | 不同机械臂与任务的动作数据 | 跨本体、跨任务的动作先验 |
| HL：高层语义子任务 | 观察、高层指令到子任务文本；再根据子任务预测动作 | 把长任务切分成可执行步骤；连接场景语义与控制 |
| WD：网页图像描述、VQA、定位 | 图文问答、检测和定位 | 广泛视觉语义和物体知识；对 OOD 物体尤其有帮助 |

###### 3. 两阶段策略的条件分解

作者把策略写成

$$
\pi_\theta(a,\hat\ell\mid o,\ell)
=\pi_\theta(a\mid o,\hat\ell)\,\pi_\theta(\hat\ell\mid o,\ell).
$$

各符号含义：

- $o$：当前视觉图像和机器人本体状态；
- $\ell$：用户给的整体任务，例如“清理卧室”；
- $\hat\ell$：模型下一步语义子任务，例如“拿起枕头”；
- $a$：以子任务为条件的连续机器人动作块。

这个分解把“决定做什么”与“具体怎么动”分开了，但并没有拆成两个模型：同一个 VLA 先以文本 token 输出子任务，再把它作为低层策略的条件。它类似显式思维链，但文本子任务是控制接口的一部分，不应等同于模型内部所有推理过程。

###### 4. 为什么预训练用 FAST，后训练加 flow matching

FAST 把一段高维连续动作压缩成较短离散 token 序列，便于以语言模型熟悉的下一 token 预测方式扩展训练。代价是控制时自回归解码动作 token 可能慢，而且离散量化会损失动作细节。

后训练加入较小的动作专家。给定动作块真值 $a$、噪声 $\omega$ 和时间 $\tau$，构造中间带噪动作 $a^{\tau,\omega}$，训练专家预测 flow 方向。推理时从噪声出发，迭代若干次（本文为 10 步）得到连续动作块。于是：

- 离散动作交叉熵有利于大规模、多源预训练；
- 连续 flow matching 有利于实时、细粒度动作生成；
- 文本预测损失仍保留，让模型继续回答视觉语言问题和预测子任务。

式 (1) 的第一项是文本/离散 token 交叉熵，第二项是连续动作向量场的平方误差，$\alpha$ 控制两项相对权重。后训练的 $\alpha=10$。原文对 flow 时间方向的符号约定应以其实现为准；按论文写法，监督目标为 $\omega-a$，不要仅凭常见 flow matching 记法替换正负号。

###### 5. 实验结果支持什么、不支持什么

- **支持**：在作者的机器人平台、家务集合和新家庭测试中，异质数据协同训练与目标域微调可以帮助模型完成多阶段任务；104 个训练地点的模型在所测任务上的平均分接近包含测试家庭数据的控制模型。
- **支持**：ME 和 CE 对多个操作任务的重要性体现在消融中；网页数据对分布外物体的语言跟随、高层推理和抽屉收纳更重要；VI 对高层策略表现有显著贡献。
- **支持**：完整 π0.5 优于论文所用 π0 与 π0-FAST+Flow 基线；高层子任务推断通常有益，训练时保留高层标签即使运行时不显式预测，也能获得部分收益。
- **不能推出**：模型对任意新家、任意物品、任意语言表达都能可靠工作；少量家庭任务成功不等于开放世界的普遍保证。
- **不能推出**：网页数据单独带来全部语义泛化，或某一种数据源在所有任务上都不可替代。逐任务拆解显示各任务的数据依赖不同。
- **比较的边界**：实验只覆盖作者定义的机器人平台、训练方案、评估场景和任务评分；人类 oracle 高层基线也不是全任务的人类能力上界。

###### 6. 关键工程选择及其含义

机器人用四路相机做高层推理，低层推理使用腕部及前向相机；动作空间为 18–19 维，动作块长度 50 帧；控制频率 50 Hz。模型直接输出目标姿态和底盘速度，由简单 PD 控制器跟踪，没有额外碰撞检测或轨迹规划。这说明论文的端到端链路覆盖感知到动作决策，但物理安全并非由文中描述的独立规划器保障。对陌生把手、遮挡和可达性等失败，作者也将其列为局限。

##### 批注：π0.5 为什么对 prefix 使用双向注意力，而 LLM 常使用因果注意力

这个问题要把 **attention mask（注意力掩码）** 和 **loss mask（损失掩码）** 分开。两者都叫“mask”，但控制的对象不同：

- **attention mask** 决定当前 token 的表示在每一层能读取哪些 token。它决定信息能否流动。
- **loss mask** 决定哪些输出位置参与交叉熵损失。它决定模型是否被要求预测某个 token。

因此，“图像和 prompt 不需要预测”首先意味着它们通常不参与输出损失；这件事本身并不自动推出它们必须使用双向注意力。一个 decoder-only LLM 也可以把 prompt 排除出 loss，同时仍然对整个序列使用因果注意力。π0.5 选择双向 prefix attention，是因为它把图像、任务指令和机器人状态当作一个需要联合编码的条件前缀，而不是把它们当作要按顺序生成的文本。

**1. 普通 decoder-only LLM 中的 prompt。** 假设序列是

```text
[prompt tokens] [response tokens]
```

标准 decoder-only LLM 通常使用因果掩码。若第 $i$ 个 token 作为 query、第 $j$ 个 token 作为 key，则允许注意力的大致条件是

$$
M_{ij}=1\quad\Longleftrightarrow\quad j\leq i.
$$

所以 prompt 内部也有方向性：prompt 的早期 token 看不到后面的 prompt token；prompt 最后一个 token 可以看到整个 prompt；response token 可以看到完整 prompt 以及已经生成的 response token。指令微调时通常只对 response 计算 loss：

$$
\mathcal{L}
= -\sum_{i\in\text{response positions}}
\log p_\theta(y_i\mid y_{<i},x).
$$

这里 prompt $x$ 没有被要求重新生成，但它仍然可以作为 response 的条件。很多人记得“训练时 prompt 被 mask”，实际经常指的是 **prompt 的 loss 被 mask 掉**，而不是 prompt 在 attention 中完全不可见。

**2. π0.5 中的 prefix 是什么。** π0.5 的 prefix 包括图像 patch、任务 prompt 和本体感知状态。它们在当前时刻已经全部给定，例如：

```text
[image patches] ["put the dishes in the sink"] [robot state]
```

这些 token 不需要由模型从左到右生成，因此论文给它们使用 full prefix mask。用 $P$ 表示 prefix，含义是

$$
\forall p_i,p_j\in P,\qquad M_{ij}=1.
$$

也就是每个 prefix token 都可以读取其他 prefix token。图像 patch 可以互相交换信息，任务指令可以和所有视觉 patch 结合，机器人状态也可以参与这个联合条件表示。随后，输出 token 读取这个已经编码好的 prefix：

$$
\text{output}_i\;\leftarrow\;P.
$$

这里的“双向”主要描述 prefix 内部的相互注意，并不表示 prefix 可以读取尚未生成的动作或文本输出。它也不表示模型完全取消了所有因果约束。

**3. π0.5 的三类 token 使用不同掩码。** 根据论文正文 §IV-A、附录 E 和图 18，可以把规则写成：

| Token 类型 | 能读取的内容 | 原因 |
|---|---|---|
| 图像、prompt、本体状态 | 整个 prefix | 它们是已知条件，需要联合编码 |
| FAST 离散动作 token $y_i$ | prefix 和此前的 FAST token $y_{<i}$ | FAST 动作是自回归生成的，必须防止未来 token 泄漏 |
| 连续动作专家 token | prefix 和整个动作专家序列 | flow matching 一次处理整个带噪动作块，动作位置可以并行协调 |
| FAST token 与动作专家之间 | 互相不可见 | 防止离散动作表示和连续动作表示发生信息泄漏 |

因此，π0.5 的掩码不是“全双向”或“全因果”二选一，而是一个混合掩码：

```text
Prefix ↔ Prefix
FAST_i → Prefix + FAST_1 ... FAST_{i-1}
ActionExpert_i → Prefix + ActionExpert_1 ... ActionExpert_H
FAST ↛ ActionExpert
ActionExpert ↛ FAST
```

上面的箭头表示“可以读取”。最后两条表示两种动作表示之间不直接互相读取；论文还特别说明信息从 VLM 单向流向动作专家，VLM 表示不会反过来读取动作专家。

**4. 为什么连续动作专家可以双向。** π0.5 的连续动作不是按 $a_t,a_{t+1},\ldots$ 逐个自回归生成，而是对长度为 $H+1=50$ 的动作块加入噪声：

$$
a_{t:t+H}^{\tau,\omega}
=\tau a_{t:t+H}+(1-\tau)\omega.
$$

动作专家要预测整个动作块的 flow 向量场。第 $i$ 个动作位置不仅应该知道前面如何移动，也应该知道后面大致要到达什么状态。双向注意力允许动作块内部建立全局协调关系，使轨迹更容易保持平滑、连贯并符合整体任务。

如果改成因果掩码，动作专家会变成类似

$$
\hat v_i
=f_i(a_1^{\tau,\omega},\ldots,a_i^{\tau,\omega},P),
$$

而不是读取整个动作块。这样不会必然导致实现无法运行，因为所有位置仍可并行前向计算；但它人为限制了动作块内部的信息流，使早期动作位置看不到后面的目标和轨迹约束。对需要整体规划的动作块，这通常会削弱表示能力。它还违背了连续动作专家“非自回归、整段动作联合建模”的设计意图。

**5. 为什么 FAST 动作仍然要因果掩码。** FAST token 是离散化后的自回归动作表示，训练目标近似为

$$
p(y_i\mid y_{<i},P).
$$

如果训练时让 $y_i$ 看到真实的未来动作 $y_{>i}$，模型可以利用答案本身降低训练损失；但推理时未来 token 尚未生成，模型就会遇到训练和推理分布不一致。因此 FAST token 必须保留因果掩码。这里的“动作”虽然也是机器人动作，但它的生成方式和连续 flow matching 动作专家不同，所以掩码也不同。

**6. 如果把所有部分都改成因果掩码，会发生什么。**

- 对图像和 prompt：prefix 内部信息交流变成单向，图像 patch 的顺序和 prompt 的词序会被人为放大；条件编码可能变弱，但模型不一定立刻失效。
- 对连续动作专家：动作块内部只能按位置单向交流，整体轨迹协调能力可能下降。
- 对 FAST 动作：这是合理的，因为它本来就是自回归目标。
- 对高层文本子任务：如果按 token 自回归生成，仍应防止高层输出中的未来 token 泄漏。

反过来，如果把 FAST 或高层文本输出改成双向注意力，训练时就可能看见尚未生成的真实目标，造成标签泄漏；如果把 prompt 也加入预测损失，则模型还会被额外要求重建输入，但这并不是 VLA 控制目标。

**7. 最准确的记忆方式。** 不要记成“prompt 永远不会被 mask”，而要记成下面三句话：

1. prompt 是否参与预测，由 **loss mask** 决定；
2. prompt 内部能否相互读取，由 **attention mask** 决定；
3. π0.5 把图像、任务 prompt 和状态作为联合条件前缀，因此使用双向 prefix attention；把 FAST 和高层文本当作自回归输出，因此保留因果 attention；把连续动作块当作并行 flow matching 输出，因此动作专家内部使用双向 attention。

这也解释了为什么“VLA 中 prompt 不需要预测”是正确观察，但还需要补充一步：**不需要预测只说明它是条件，是否双向还取决于模型希望怎样编码这个条件以及输出是否存在未来信息泄漏。**

#### 批注：VLA 中 prompt 的注意力掩码与损失掩码

这次讨论的核心是：**prompt 不需要预测，不等于 prompt 在 attention 中必须被遮住；attention mask 和 loss mask 是两件不同的事。**

- **Attention mask（注意力掩码）**决定一个 token 在 Transformer 每一层可以读取哪些 token，控制信息如何流动。
- **Loss mask（损失掩码）**决定哪些输出位置参与交叉熵损失，控制模型是否被要求预测这些位置。

例如指令微调的序列可以写成：

```text
[prompt tokens] [response tokens]
```

通常只对 response 计算损失：

$$
\mathcal{L}
= -\sum_{i\in\text{response positions}}
\log p_\theta(y_i\mid y_{<i},x).
$$

这里 prompt $x$ 没有被要求重新生成，但它仍然是 response 的条件。很多资料说“训练时把 prompt mask 掉”，通常指 **prompt 的 loss 被 mask 掉**，而不是 attention 中完全不允许读取 prompt。

标准 decoder-only LLM 通常对整个序列使用因果注意力：

$$
M_{ij}=1
\quad\Longleftrightarrow\quad
j\leq i.
$$

因此 prompt 内部也有方向性：早期 prompt token 看不到后面的 prompt token；prompt 的最后一个 token 可以看到整个 prompt；response token 可以看到完整 prompt 和之前已经生成的 response token。这里 prompt 不参与 loss，但仍参与 attention。

π0.5 的做法更接近一个多模态 encoder-decoder 条件接口。图像 patch、任务 prompt 和机器人本体状态都是当前时刻已经给定的条件，不需要从左到右生成，所以论文对这部分使用 full prefix mask：

$$
\forall p_i,p_j\in P,
\qquad M_{ij}=1,
$$

其中 $P$ 是 prefix。也就是说，图像 patch、任务指令和机器人状态可以彼此读取，联合形成当前观察的条件表示。输出 token 可以读取这个完整 prefix，但 prefix 不会读取尚未生成的输出。

π0.5 并不是整个模型都使用双向注意力，而是混合掩码：

| 部分 | 注意力规则 | 原因 |
|---|---|---|
| 图像、prompt、本体状态 | prefix 内双向注意 | 它们是已知条件，需要联合编码 |
| FAST 离散动作 token | prefix + 之前的 FAST token | FAST 动作是自回归预测，必须防止未来泄漏 |
| 高层文本子任务 | 按 token 自回归生成时使用因果约束 | 子任务文本本身是输出目标 |
| 连续动作专家 token | prefix + 整个动作专家序列 | flow matching 一次处理完整动作块，可并行协调 |
| FAST 与动作专家之间 | 互相不可见 | 防止两种动作表示信息泄漏 |

连续动作专家和 FAST 动作不能因为都叫“动作”就使用同一种 mask。FAST 是离散 token 的自回归生成：

$$
p(y_i\mid y_{<i},P).
$$

如果 $y_i$ 看到真实未来动作 $y_{>i}$，训练时就会发生标签泄漏，推理时又不存在未来 token，造成训练和推理不一致。

连续动作专家则接收整个带噪动作块：

$$
a_{t:t+H}^{\tau,\omega}
=\tau a_{t:t+H}+(1-\tau)\omega.
$$

它并行预测整个动作块的 flow 向量场。使用双向注意力可以让动作块中的各个时间位置共同协调轨迹；若改成因果掩码，早期动作位置看不到后面的目标和轨迹约束，整体动作一致性可能变差，但前向计算仍然可以并行进行。

因此最准确的记忆方式是：

1. **是否参与预测**，由 loss mask 决定；
2. **能否读取其他 token**，由 attention mask 决定；
3. π0.5 的图像、任务 prompt 和状态是联合条件前缀，使用双向 prefix attention；FAST 和高层文本是自回归输出，使用因果 attention；连续动作块由 flow matching 并行生成，动作专家内部使用双向 attention。

所以“VLA 中 prompt 不需要预测”这个判断是对的，但它只说明 prompt 是条件输入；prompt 是否双向，还取决于模型如何编码条件，以及是否存在未来信息泄漏。



#### 批注补充：结合训练流程和推理流程理解双向注意力

前面的解释容易把两个问题混在一起：

1. **动作块内部的不同位置能不能互相读取？** 这是 attention mask 的问题。
2. **模型是在一次前向中预测整段动作，还是按 token/迭代步骤生成？** 这是输出建模方式的问题。

π0.5 的关键是：**连续动作块内部可以双向注意，但高层文本和 FAST 离散动作仍按自回归方式生成；flow matching 的多次去噪迭代之间也仍然有先后顺序。**

##### 一、训练流程

###### 1. 先构造已知的 prefix

在某个训练样本中，模型拿到当前观察和任务指令：

```text
P = [图像 patch] [任务 prompt] [机器人本体状态]
```

例如：

```text
P = [厨房图像] ["put the dishes in the sink"] [关节与底盘状态]
```

这个 (P) 在当前训练样本中已经完整给定。它不是需要模型生成的答案，因此通常不对这些位置计算输出损失。但是，π0.5 允许 prefix 内部双向注意：

$$
\forall p_i,p_j\in P,
\qquad M_{ij}=1.
$$

这表示图像 patch 可以互相读取，任务 prompt 可以与所有图像 patch 交互，机器人状态也可以与视觉和语言条件交互。这样得到的是一个联合的场景条件表示。

这里要特别区分：

- prefix **不参与 loss**，表示不要求模型重建图像、prompt 或状态；
- prefix **可以参与 attention**，表示动作或文本输出可以读取它，而且 prefix 内部也可以互相读取。

所以“prompt 不需要预测”并不等于“prompt 必须被 attention mask 遮住”。

###### 2. FAST 离散动作分支：训练时是自回归的

预训练阶段，动作被 FAST tokenizer 编码成离散 token。序列可以抽象成：

```text
[P] [a₁] [a₂] [a₃] ...
```

FAST 分支学习的是：

$$
p(a_i\mid P,a_{<i}).
$$

因此使用因果掩码：

- (a_1) 能看 prefix，但不能看 (a_2,a_3,ldots)；
- (a_2) 能看 prefix 和 (a_1)；
- (a_3) 能看 prefix、(a_1) 和 (a_2)。

如果训练时让 (a_1) 看到真实的 (a_2,a_3)，模型就可以利用未来答案来降低训练损失；但推理生成 (a_1) 时，未来 token 还不存在。这就是标签泄漏和训练-推理不一致。

###### 3. 连续动作专家分支：训练时一次处理整个动作块

后训练阶段，π0.5 还训练一个 flow matching 动作专家。它不是把动作编码成“先 (a_t)、再 (a_{t+1})、再 (a_{t+2})”的离散序列，而是直接取一个完整动作块：

$$
a_{t:t+H}
\in\mathbb{R}^{(H+1)\times d}.
$$

然后采样噪声 (omega) 和时间步 (	au)，构造带噪动作块：

$$
a_{t:t+H}^{\tau,\omega}
=\tau a_{t:t+H}+(1-\tau)\omega.
$$

动作专家要为整个动作块预测向量场：

$$
V=[v_t,v_{t+1},\ldots,v_{t+H}].
$$

因为目标是**同时预测整段动作的向量场**，动作专家内部使用双向注意力：

$$
v_i
=f_i\left(P, a_t^{\tau,\omega},\ldots,a_{t+H}^{\tau,\omega}\right).
$$

因此，预测第 (i) 个位置的向量 (v_i) 时，可以读取动作块中其他位置的当前带噪值。这样模型能同时考虑：

- 前面的动作应该如何移动；
- 后面的动作最终要到达什么状态；
- 整段轨迹是否连续、平滑、协调。

这不违反自回归约束，因为这个分支本来就不是在学习 (p(a_i\mid a_{<i}))。它学习的是给定整个带噪动作块后的联合向量场。

##### 二、推理流程

推理时需要区分两种输出：高层文本子任务和低层连续动作块。

###### 1. 先自回归生成高层子任务

输入仍是完整 prefix：

```text
[P] = [图像] [“clean the bedroom”] [机器人状态]
```

模型先生成语义子任务，例如：

```text
“pick up the pillow”
```

如果这个子任务由多个文本 token 组成，就按自回归方式生成：

$$
p(y_i\mid P,y_{<i}).
$$

此时高层文本 token 使用因果注意力。生成第 (i) 个文字时，可以读取完整 prefix 和已经生成的文字，但不能读取尚未生成的未来文字。

###### 2. 初始化一个完整的噪声动作块

高层子任务生成后，动作专家接收：

```text
[P] [高层子任务] [完整噪声动作块]
```

初始动作块可以表示为：

$$
A^{(0)}
=\left[a_t^{(0)},a_{t+1}^{(0)},\ldots,a_{t+H}^{(0)}\right].
$$

这里 (A^{(0)}) 的所有时间位置在同一次前向中存在。动作专家内部可以双向读取：

$$
A_i^{(k)}\leftrightarrow A_j^{(k)}.
$$

这意味着在第 (k) 次去噪前向中，动作块内部不是“第一个位置先生成、第二个位置再生成”，而是所有位置共同计算。

###### 3. 每一次去噪前向内部是双向的

第 (k) 次 flow matching 前向可以写作：

$$
V^{(k)}
=f_\theta\left(P,\hat\ell,A^{(k)}\right),
$$

其中 (hat\ell) 是已经生成的高层子任务，(A^{(k)}) 是当前的完整带噪动作块。由于动作专家内部使用双向注意力，某个位置的预测可以写成：

$$
v_i^{(k)}
=f_i\left(P,\hat\ell,
 a_t^{(k)},\ldots,a_{t+H}^{(k)}
ight).
$$

随后更新整个动作块：

$$
A^{(k+1)}
=A^{(k)}+\Delta_k V^{(k)}.
$$

论文使用多次去噪迭代，文中描述为 10 步。流程是：

```text
完整噪声动作块 A^(0)
        ↓ 双向注意力
第 1 次向量场预测与更新
        ↓ 双向注意力
第 2 次向量场预测与更新
        ↓
        ⋮
        ↓ 双向注意力
第 10 次向量场预测与更新
        ↓
连续动作块 A^(10)
```

因此必须区分两种“顺序”：

- **动作块内部的时间位置**：一次前向中可以双向交互；
- **flow matching 的去噪迭代**：第 (k+1) 步依赖第 (k) 步，仍然按顺序执行。

所以“双向动作注意力”不等于“整个推理过程一次完成”，也不等于“去掉了所有时间顺序”。

##### 三、如果连续动作专家改用因果掩码

改成因果掩码后，第 (i) 个动作位置只能读取前面的位置：

$$
\tilde v_i^{(k)}
=\tilde f_i\left(P,\hat\ell,
 a_t^{(k)},\ldots,a_i^{(k)}\right).
$$

这通常不会让程序无法运行，因为 Transformer 仍然可以一次并行计算所有位置；但是信息流被限制为单向，早期动作位置看不到后续动作位置当前的状态和整体轨迹约束。潜在后果是：

- 动作块整体协调能力变弱；
- 早期动作更难根据最终目标调整；
- 轨迹平滑性和长程一致性可能下降；
- flow matching 的并行整段建模优势被部分削弱。

而如果把 FAST 或高层文本改成双向注意力，问题相反：训练时每个 token 可能看到真实未来目标，产生标签泄漏，推理时却没有这些未来 token。

##### 四、用一句话记忆整个过程

> **训练时，prefix 作为完整条件使用双向注意力；FAST 离散动作作为自回归目标使用因果注意力；连续动作专家对完整带噪动作块联合预测，因此动作块内部使用双向注意力。推理时，先因果生成高层子任务，再在每一次 flow matching 去噪前向中对整段动作块使用双向注意力，但不同去噪迭代之间仍按顺序进行。**

#### 批注补充：把混合注意力写成完整的 row-column 矩阵

我之前用箭头写“FAST 可以读取 prefix”“动作专家可以读取 prefix”，但箭头没有明确展示 prefix 位于矩阵的哪一组列，容易造成“prefix column 不存在”的误解。下面采用固定约定：

- **行 row 是 query**：当前正在计算表示的 token；
- **列 column 是 key/value**：当前 query 可以读取的 token；
- 矩阵中的 `1` 表示允许读取，`0` 表示禁止读取；
- 这是概念矩阵。具体代码可能使用 `0` 表示允许、`-inf` 表示禁止，或使用 bool mask，但允许关系相同。

设总序列按三类 token 排列：

```text
[P1 ... Pm] [F1 ... Fn] [A1 ... AH]
```

其中：

- $P$：prefix，包括图像 patch、任务 prompt、机器人本体状态；
- $F$：FAST 离散动作 token；
- $A$：连续动作专家 token。

整个 attention mask 仍然是一个方阵，因为总共有 $m+n+H$ 个 token：

$$
M\in\{0,1\}^{(m+n+H)\times(m+n+H)}.
$$

按 token 类别分块时，**行对应左侧 query 类别，列对应上方 key 类别**：

| 行 query / 列 key | Prefix 列 | FAST 列 | 动作专家列 |
|---|---:|---:|---:|
| Prefix 行 | $M_{PP}=1$：prefix 内双向 | $M_{PF}=0$ | $M_{PA}=0$ |
| FAST 行 | $M_{FP}=1$：读取完整 prefix | $M_{FF}=L_n$：下三角因果矩阵 | $M_{FA}=0$ |
| 动作专家行 | $M_{AP}=1$：读取完整 prefix | $M_{AF}=0$ | $M_{AA}=1$：动作专家内部双向 |

这里 $L_n$ 是 FAST token 的下三角因果矩阵：

$$
(L_n)_{ij}=1
\quad\Longleftrightarrow\quad
j\leq i.
$$

因此，prefix 列明确存在于矩阵最左侧，而且 FAST 行和动作专家行都能读取这些列。只有 prefix 行不会读取 FAST 和动作专家列；这体现的是“条件输入不反向读取输出表示”，不是 prefix 被删除了。

当 $m=2$、$n=3$、$H=2$ 时，完整矩阵可以画成下面这样。列标题是 key，行标题是 query：

```text
                 key columns
          P1  P2  F1  F2  F3  A1  A2
query P1   1   1   0   0   0   0   0
      P2   1   1   0   0   0   0   0
      F1   1   1   1   0   0   0   0
      F2   1   1   1   1   0   0   0
      F3   1   1   1   1   1   0   0
      A1   1   1   0   0   0   1   1
      A2   1   1   0   0   0   1   1
```

逐行解释：

- `P1` 行：可以看 `P1,P2`，不能看 FAST 或动作专家；
- `F1` 行：可以看 `P1,P2` 和自己 `F1`，不能看未来 `F2,F3`；
- `F2` 行：可以看完整 prefix、`F1` 和自己 `F2`；
- `A1` 行：可以看完整 prefix 和 `A1,A2`，不能看 FAST；
- `A2` 行：同样可以看完整 prefix 和动作专家 token。

用注意力计算式看，若第 $i$ 行是 query、第 $j$ 列是 key，则：

$$
\operatorname{Attention}(Q,K,V)_i
=\sum_j M_{ij}\,\alpha_{ij}V_j.
$$

其中 $\alpha_{ij}$ 是 softmax 后的注意力权重。于是：

- 对 FAST 行 $F_i$，prefix 列 $P_1,\ldots,P_m$ 的 $M_{ij}=1$，所以 FAST 可以读取完整 prefix；
- 对动作专家行 $A_i$，prefix 列同样全为 1，所以每个动作位置都能读取图像、prompt 和状态；
- 对 prefix 行，FAST 列和动作专家列为 0，所以 prefix 不读取输出 token；
- 动作专家列 $A$ 对动作专家行全为 1，因此同一次前向内所有动作位置可以互相协调。

这也解释了为什么之前的箭头

```text
FAST_i → Prefix
ActionExpert_i → Prefix
```

如果约定箭头表示“query 读取 key”，其实已经表达了 prefix 列存在；但它没有展示矩阵的列布局。完整矩阵才直接显示：**prefix 是所有输出 query 都可以读取的左侧 key 列块。**

在训练和推理中，这个矩阵的结构保持一致，变化的是 token 的来源：

- 训练时，FAST token 通常来自真实动作的 FAST 编码，用因果 mask 训练 next-token loss；连续动作专家接收真实动作加噪后的完整动作块，用双向 mask 预测 flow vector field；
- 推理时，高层文本或 FAST token 按自回归方式逐步生成；连续动作专家在每一次 flow matching 去噪前向中接收整个当前动作块，因此仍使用动作专家内部的双向 mask；不同去噪迭代 $k\to k+1$ 之间仍有顺序。

### 全文主线（滚动更新）

- **研究问题**：自回归 VLA 需要把连续动作变成离散 token；逐维、逐时间步的简单分箱在高控制频率下产生长且高度相关的 token 序列，使 next-token 学习容易退化为复制最近动作，难以学习灵巧操作。
- **核心贡献**：提出 FAST（Frequency-space Action Sequence Tokenization），用 DCT 把动作块变到频域，再用量化和 BPE 压缩；提出在约 100 万条真实机器人 1 秒动作块上训练的通用 tokenizer FAST+。
- **方法主线**：分位数归一化 → 对每个动作维度做 DCT → 乘尺度并取整 → 低频优先展平整数矩阵 → 用 BPE 合并重复/常见片段 → 自回归 VLA 预测压缩后的动作 token，并通过逆 BPE、逆量化和逆 DCT还原连续动作。
- **关键结论**：在论文评测中，FAST 显著减少动作 token，尤其在 20–50 Hz 的任务上；它使 π0/OpenVLA 能训练高频、灵巧任务，并使 π0-FAST 在跨机器人数据上达到接近 diffusion π0 的表现，同时训练所需 GPU 时间最多减少约 5 倍。
- **主要限制**：自回归解码推理较慢；论文实际策略评测主要集中于静态机械臂，移动机器人、灵巧手和人形机器人的 FAST+ 结果主要是离线压缩评估；压缩率与重建误差仍由量化尺度控制。

##### 要点与大意

1. 论文把策略写成
   \[
   \pi(a_{1:H}\mid o),\qquad a_{1:H}\in\mathbb{R}^{H\times D},
   \]
   其中 \(o\) 是观测，\(H\) 是动作块长度，\(D=|A|\) 是动作维度。tokenizer 要构造 \(T_a:a_{1:H}\mapsto[T_1,\ldots,T_n]\)，\(T_i\) 属于 VLA 的离散词表；\(n\) 可以随动作块变化。
2. 旧方法对每个时间步、每个动作维度独立分箱。若每个动作块有 \(H\) 步、\(D\) 维，则序列长度约为 \(HD\)；控制频率越高，单位时间的步数越多，但相邻动作变化通常越小，token 的边际信息量下降。论文的 toy spline 实验显示，采样频率升高时，naive 模型会趋向复制第一个动作。
3. FAST 利用动作轨迹通常在时间上平滑这一事实：低频 DCT 系数描述整体轨迹，高频系数描述快速变化和尖锐跳变。把系数稀疏化后，BPE 再合并频繁的整数片段，能同时缩短序列并保留细粒度动作信息。
4. 论文报告的 1 秒动作块平均 token 数为：BridgeV2（5 Hz，7 维）naive 35、FAST 20；DROID（15 Hz，7 维）105、29；Table Bussing（20 Hz，7 维）140、28；T-Shirt Folding（50 Hz，14 维）700、53。对应压缩比约为 1.75、3.6、5.0、13.2，说明频率越高、时间冗余越强时收益越明显。
5. FAST+ 的 BPE 词表在约 100 万个 1 秒动作块上训练，覆盖单臂、双臂、移动操作机器人，以及 joint、end-effector 等动作空间。作者在未参与 tokenizer 训练的多种数据集上报告至少约 2 倍的 token 数减少，并称其策略性能接近按数据集单独拟合的 FAST。
6. 在策略实验中，naive tokenization 在 Table Bussing（20 Hz）和 T-Shirt Folding（50 Hz）上无法取得进展；FAST 和 FSQ 都能训练，但 FAST 在真实灵巧任务上通常更好。OpenVLA + FAST 也显著优于 OpenVLA 的原始分箱方案，说明收益并不依赖某一个 VLA backbone。
7. 与 diffusion π0 的比较中，小数据集上的任务表现相近；大数据集上 π0-FAST 收敛更快。跨具身的 903M timestep 数据训练中，π0-FAST 的总体任务表现接近 diffusion π0，论文报告训练 GPU 时间最多减少约 5 倍。

##### 数学原理与推导

- **适用性**：直接涉及。
- **符号与形状**：动作块 \(a\in\mathbb{R}^{H\times D}\)；第 \(d\) 维时间序列为 \(a_{:,d}\in\mathbb{R}^{H}\)；DCT 系数矩阵 \(C\in\mathbb{R}^{H\times D}\)；量化后是整数矩阵 \(\bar C\)；展平后是整数序列，BPE 输出长度为可变的 \(n\)。论文的图示按“每一列对应一个频率、先放低频”来组织矩阵；实现时应以作者代码的确切排列约定为准。
- **归一化**：论文把训练集每个动作维度的第 1 和第 99 分位数映射到 \([-1,1]\)，以降低异常值和跨机器人尺度差异的影响。若用 \(q_{.01,d},q_{.99,d}\) 实现，可先裁剪再线性映射；这条具体裁剪公式是实现草图，论文正文没有给出逐元素公式。
- **DCT（实现草图）**：对每个动作维度使用常见的 DCT-II 形式
  \[
  C_{k,d}=\sum_{t=0}^{H-1}\tilde a_{t,d}\cos\!\left[\frac{\pi}{H}\left(t+\tfrac12\right)k\right],
  \quad k=0,\ldots,H-1.
  \]
  低 \(k\) 表示慢变化的整体轨迹，高 \(k\) 表示快速变化。论文说明使用 DCT，但没有在正文固定归一化常数；复现时必须与逆 DCT 使用同一 convention。
- **量化**：
  \[
  \bar C_{k,d}=\operatorname{round}(\gamma C_{k,d}),
  \]
  其中 \(\gamma\) 是精度—压缩率旋钮。\(\gamma\) 越大，保留的整数精度通常越高、token/重建成本可能越大；论文单数据集实验常用 \(\gamma=10\)。
- **展平与 BPE**：把 \(\bar C\) 按低频优先展平为 \(x=[x_1,\ldots,x_m]\)，在训练动作集合上拟合 BPE 词表 \(\Phi\)，得到 \(T=\operatorname{BPE}(x;\Phi)\)。BPE 对整数序列的合并是无损的，但整个 FAST 过程仍可能有损，因为量化和系数截断带来重建误差。
- **逆变换**：推理时先做 \(x=\operatorname{BPE}^{-1}(T;\Phi)\)，再 reshape 成系数矩阵、除以 \(\gamma\)，执行 inverse DCT，并反归一化回机器人动作空间。若归一化、DCT convention、展平顺序或 gamma 不一致，token 无法正确还原动作。
- **与 next-token 学习的关系**：自回归目标是 \(\sum_i\log p(T_i\mid T_{<i},o)\)。naive 分箱让高频平滑轨迹的相邻 token 高度可预测，单步损失可能很低但对未来轨迹形状学习不足；FAST 把全局形状和较高信息量的频率系数提前暴露给模型，改善每一步预测的有效信息。
- **边界情况**：如果动作信号本身有大量高频、非平滑跳变，低频优先不一定足够，必须通过 \(\gamma\) 和重建误差检查保真度；如果动作维度尺度或控制频率超出 FAST+ 训练分布，通用词表的压缩率和策略性能不能直接假定。

##### 代码实现

- **性质**：论文给出 FAST+ 的公开接口示例；下面的流程是基于论文的实现草图，不声称等同于作者仓库的内部实现。
- **代码位置**：本文未附带作者代码仓库；论文中给出 `physical-intelligence/fast` 的 Hugging Face `AutoProcessor` 接口。
- **数据流与张量形状**：输入一个 1 秒动作块 `action_chunk`，形状可抽象为 `[H, D]`；逐维归一化和 DCT 后仍为 `[H, D]`；展平为 `[H*D]` 的整数流，再经 BPE 变为长度 `n` 的 token id 序列；解码后恢复 `[H, D]`。
- **作者给出的接口**：

```python
from transformers import AutoProcessor

tokenizer = AutoProcessor.from_pretrained(
    "physical-intelligence/fast",
    trust_remote_code=True,
)
tokens = tokenizer(action_chunk)
```

  若需要针对某个数据集重新拟合 BPE 词表，论文还给出 `new_tokenizer = tokenizer.fit(action_dataset)` 的接口。
- **复杂度 / 数值稳定性**：DCT 可用快速算法实现；BPE 的主要收益来自减少自回归步数，但词表训练和动作预处理仍有成本。需要保存训练集分位数、\(\gamma\)、DCT 的归一化约定、展平顺序和 BPE 词表；否则不能可靠复现 detokenization。
- **验证方法**：至少检查四项：① `decode(encode(a))` 的形状是否回到 `[H,D]`；② 在固定 gamma 下测逐维最大绝对误差和 MSE；③ 统计不同频率数据的平均 token 数；④ 对一个已知动作块比较逆 DCT 前后的系数，并验证 BPE 是无损展开。策略训练时还应确认 action loss 只对动作 token 计算，且推理使用与训练相同的 chunk 长度和词表。

##### 证据、限制与延伸

- **直接证据**：Algorithm 1 和图 4 给出归一化、DCT、量化、展平、BPE 的流水线；表 I 给出 token 数压缩；图 6 给出 naive/FSQ/FAST/FAST+ 的策略比较；图 9、图 11 比较 π0-FAST 与 diffusion π0；附录 C/D 给出训练超参数和 DROID 设定。
- **实验细节**：大多数策略使用 π0（PaliGemma-3B）或 OpenVLA（Prismatic 7B）骨干，输入图像通常为 \(224\times224\)，动作块为 1 秒；训练使用 AdamW、线性 warmup 1000 steps、学习率 \(5\times10^{-5}\)、梯度范数裁剪 1、EMA 衰减 0.999。DROID 训练使用 75k 成功 episode、约 21M samples、240k iterations；论文报告 3B 模型在 8×H100 上约 4 天。上述是论文设定，不代表在本地环境已复现。
- **推理代价**：论文报告 NVIDIA 4090 上 diffusion π0 生成 1 秒动作块约 100 ms，而 π0-FAST 约 750 ms；FAST 通常要自回归解码 30–60 个 token，diffusion 对照约 10 步。FAST 因而换取较快训练和更直接的离散语言式解码，牺牲在线推理速度。
- **关键限制**：论文的真实策略实验主要是静态机械臂和若干仿真/桌面任务；FAST+ 对移动、灵巧手、人形和导航数据的广泛压缩结果不能替代这些形态上的闭环策略验证。论文也没有给出对所有控制频率、动作空间或突发跳变信号的普适误差保证。
- **与其他方法的联系**：FAST 与语言 BPE 的共同点是先把高冗余序列压成更少的高信息量符号；它与 FSQ/VQ 的差别在于 DCT 是解析变换，只有 BPE 词表需要学习，避免训练一个动作自编码器。FAST 本身是动作表示/解码层，不等同于策略架构；它可以接在不同的自回归 VLA backbone 前面。
- **待核验问题**：需要在目标机器人上实测 gamma、chunk 长度、动作控制频率和闭环延迟；需要检查公开 `physical-intelligence/fast` 实现的 DCT 归一化、系数排列和边界处理；还需要比较同等推理延迟下 FAST、diffusion 与其他非自回归动作头的性能。

- **研究问题**：怎样让一个通用 VLA 在任务、环境、机器人本体和执行质量都很异质的数据上学习，同时保留不同策略，而不是把它们平均成一个次优动作。
- **核心方法**：π0.7 在 π0.6-MEM 的 VLA 和多尺度具身记忆上加入多模态上下文条件，包括更细的子任务指令、未来子目标图像、速度/质量/错误等 episode 元数据，以及 joint/EE 控制模式。
- **关键机制**：高层策略或人类提供下一语义子任务；轻量世界模型根据当前观察和子任务生成多视角子目标图像；低层 π0.7 以 50 步动作块和 flow matching 动作专家生成连续控制。
- **数据策略**：混合高质量示范、低质量或失败示范、旧策略的自主 rollout、人类第一视角视频、开放机器人数据和网页多模态任务；通过上下文标注让模型知道“这段行为做得怎样、采用什么策略”。
- **主要结果**：论文报告开箱即用的灵巧任务表现、复杂语言跟随、跨本体迁移和组合式新任务能力；在 UR5e 衣物折叠零样本迁移中，π0.7（带生成子目标）达到 85.6% 任务进度、80% 成功率，人类对照为 90.9% 和 80.6%。
- **主要限制**：零样本未见任务/未见本体组合的成功率通常低于已见任务；大数据集中的“真正未见”难以严格界定；子目标生成代价高，长时程任务仍需要高层指令、视觉目标或后续适配。

##### 摘要与引言：论文声称解决什么问题

π0.7 被定义为一个通用机器人基础模型，目标是让机器人在没有针对目标任务单独后训练的情况下，执行多种长时程灵巧任务。论文重点展示四类能力：

1. **开箱即用的灵巧控制**：使用咖啡机、叠衣物、取出垃圾袋、折叠盒子、削水果/蔬菜等任务。
2. **语言指令泛化**：在训练中未出现的厨房和卧室中，执行开放词汇、带空间关系或不寻常指代的指令。
3. **跨本体泛化**：把一种机器人上的技能迁移到形态、质量、可达工作空间明显不同的目标机器人。
4. **组合式任务泛化**：把训练中学到的抓取、移动、开关、擦拭等技能组合成新的任务，例如把红薯放入空气炸锅。

论文的中心判断是：只扩大数据量不够。数据中的策略和质量往往不同，例如同一任务可能有快慢不同的示范、失败 episode、RL 策略产生的自主轨迹。如果没有额外条件，模型容易把多种模式平均化。π0.7 因此把上下文扩展为多种信号：更细的语言、表示执行质量和策略的 episode 元数据、以及描述未来场景状态的子目标图像。这样模型可以在训练中学习“同一个任务有哪些做法”和“哪些做法质量更高”，测试时再按上下文选择行为。

##### II. 相关工作：在已有路线上的位置

论文把 π0.7 放在四条研究路线的交叉处：

- 通用机器人策略和预训练 VLA；
- 记忆模块，用于跨时间保留观察；
- 长时程任务的层级或子目标规划；
- 用户目标图像或生成子目标图像条件控制。

作者强调，本文主要贡献是训练配方和实证分析，而不是提出全新的 Transformer 结构。π0.7 沿用 π0.6-MEM 的模型骨架，再把异质上下文接入统一 prompt。网页视觉语言数据、人类第一视角视频和自主机器人经验被视为帮助 VLA 获得语义、物理概念和策略多样性的知识来源。

##### III. Flow-based VLA：符号、目标函数与动作块

训练数据包含机器人轨迹。观测和动作可写成：

$$
o_t=[I_t^1,\ldots,I_t^n,q_t],
$$

其中：

- $I_t^i$ 是第 $i$ 个相机在时刻 $t$ 的图像；
- $q_t$ 是机器人关节配置或状态向量；
- $a_t$ 是关节空间或末端执行器控制命令；
- $a_{t:t+H}$ 是从 $t$ 开始、长度为 $H$ 的动作块；
- $o_{t-T:t}$ 是最近一段历史观察；
- $C_t$ 是当前训练样本的上下文 prompt。

论文给出的近似训练目标是：

$$
\max_\theta\; \mathbb{E}_{D}
\left[\log \pi_\theta\left(a_{t:t+H}\mid o_{t-T:t},C_t\right)\right].
$$

它表达的是：在历史观察和上下文给定时，提高真实动作块的条件概率。flow matching 动作专家实际优化的是相应的近似下界，而不是直接得到一个闭式动作对数似然。

π0.7 使用 FAST token 训练 VLM 主干，同时使用连续 flow matching 动作专家。知识隔离（knowledge insulation，KI）训练让动作专家读取 VLM 的激活，但阻断动作专家向 VLM 主干反向传播的梯度；这样 VLM 主要由较稳定的离散交叉熵训练，动作专家负责连续动作建模。

##### IV. π0.7 总体架构

π0.7 由三部分组成：

| 部件 | 论文给出的规模/作用 |
|---|---|
| VLM 主干 | Gemma3 4B，包含约 400M 参数的视觉编码器 |
| MEM 风格历史编码器 | 对多帧观察做时间和空间压缩，输出固定数量的视觉 token |
| 动作专家 | 860M 参数的 Transformer，用 flow matching 预测连续动作 |
| 总规模 | 约 5B 参数 |

与 π0、π0.5、π0.6 的短任务文本 prompt 相比，π0.7 允许上下文在时间上和模态上更丰富。输入可以包含总体任务、下一子任务、子目标图像、episode 元数据和控制模式。训练时随机丢弃 prompt 组成，使模型测试时能使用其中任意子集。

##### V. 多样化 Prompt

###### A. 子任务指令

模型接收总体任务指令 $\ell_t$，例如“清理厨房”，还可以接收下一语义子任务 $\hat{\ell}_t$，例如“打开冰箱门”。$\hat{\ell}_t$ 可以由高层语言策略生成，也可以由人类实时提供，并且能够随时间变化。

子任务指令的作用是把长任务拆成当前要完成的语义阶段，但它不直接规定每个关节动作。π0.7 的低层策略仍根据视觉、历史状态和其他上下文产生连续动作。训练过语言跟随后，模型可以接受逐步口头 coaching；这些 coaching 轨迹还能进一步训练一个高层策略，使系统由人工指导转为自主选择下一子任务。

###### B. 子目标图像

语言“打开冰箱门”没有说明应该从哪个角度、以什么抓法接近把手。论文因此引入多视角子目标：

$$
g_t=[G_t^1,\ldots,G_t^n],
$$

其中 $G_t^i$ 是第 $i$ 个相机对应的近未来目标图像。基础相机更适合表达环境和物体状态，腕部相机更适合表达手臂、夹爪和接触关系；多视角目标合起来能提供更强的空间约束。

运行时，轻量世界模型 $g_\psi$ 根据当前观察、子任务和元数据生成子目标图像。它从 BAGEL 图像生成/编辑模型初始化，利用网页视频、图像编辑数据、人类第一视角视频和高质量机器人片段学习视觉与物理概念。其训练目标可以抽象为：

$$
\max_\psi\;\mathbb{E}_{D_g}
\left[\mathcal{L}_{\mathrm{CFM}}\left(g_t^\star,
 g_\psi(o_t,\hat{\ell}_t,m)\right)\right],
$$

其中 $g_t^\star=o_{t_{\mathrm{end}}}$ 是片段结束时的真实图像，$m$ 是 episode 元数据，$D_g$ 是带高质量子任务标注的片段集合。这里的 flow matching 用于生成图像目标，不要与机器人动作专家的 flow matching 混为一谈。

###### C. Episode 元数据

为了让模型利用混合质量数据，作者把每个 episode 的执行属性放入上下文 $m$：

- **总体速度**：episode 的时间步长度，按 500 步区间离散。例如 1750–2250 步归入“2000 steps”。
- **总体质量**：1–5 分，5 表示质量最高。
- **错误标记**：当前动作片段中是否出现错误，例如抓取失败或执行了错误子任务。

速度、质量和错误标签来自真实 episode 的统计或人工粗粒度标注。训练时，模型能学习同一任务中不同速度、质量、失误模式与动作的关系；推理时可提示“快、质量最高、无错误”。

###### D. 控制模式

π0.7 同时支持关节空间和末端执行器控制。prompt 中加入控制模式标识：

$$
c\in\{\text{joint},\text{ee}\}.
$$

因此同一个模型可以按任务选择关节目标或末端位姿目标。附录实验没有发现末端执行器控制在跨本体任务上稳定优于关节控制，所以主实验主要使用 joint 模式。

###### E. 完整 Prompt 与随机丢弃

论文给出的 prompt 结构可抽象为：

```text
<多视角观察><多视角子目标>
任务：削蔬菜。子任务：拿起削皮器。
速度：8000。质量：5。错误：否。控制模式：joint。
<本体状态>
```

训练中采用组成级 dropout：

- 每个 batch 只有约 25% 样本加入视觉子目标；
- 在有子目标图像的样本中，子任务文本约 30% 的概率被丢弃；
- episode 元数据整体约 15% 的概率被丢弃；
- 速度、质量、错误三个元数据字段各自再以 5% 概率丢弃；
- 控制模式不做 dropout。

加入子目标图像后，动作预测近似变成从当前图像到目标图像之间的逆动力学问题，因此训练显著更快；但模型仍需通过 dropout 保持没有图像目标时的能力。

##### VI. 模型与训练配方

###### A. 训练数据

训练混合物覆盖：

- 静态和移动机器人；
- 单臂和双臂平台；
- 类实验室、类家庭和真实家庭环境；
- 人类示范，包括低质量或失败 episode；
- 旧模型评测时收集的自主数据，包括 π0.6* 等策略产生的 rollout；
- 人类介入轨迹；
- 开源机器人数据集；
- 人类第一视角视频；
- 网页多模态任务，如目标定位、属性预测、视觉问答和文本预测；
- 机器人视频与网页视频的 video-language 任务。

作者排除了用于泛化能力主评测的自主数据，避免把测试任务直接混入训练。其余自主评测数据被解释成一种策略蒸馏：π0.7 通过 episode 元数据知道这些轨迹的质量和策略条件，再吸收旧策略的能力。

###### B. 主干、视觉历史和动作专家

每个机器人最多使用四个相机视图：前视图、左右腕部视图，以及可选后视图。每个视图最多带六帧历史图像，历史采样步长为 1 秒；相机和子目标图像调整到 $448\times448$。历史帧由 MEM 风格视觉编码器压缩成与单帧相同数量的 token；子目标图像使用同一编码器。

模型还输入机器人本体状态及其历史。π0.6 中状态被离散成文本 token；π0.7 改用线性投影把状态维度映射到 backbone 维度，每个历史状态作为单独 token。若对应历史视觉帧被丢弃，状态 token 也被 mask。

注意力采用 block-causal 结构：观察 token 和子目标图像 token 在各自块内双向注意；子目标图像块可以读取观察；后续文本 token 使用因果注意力。动作专家读取 VLM 的激活，并在自己的 50 个动作 token 内使用双向注意。

###### C. 动作专家、RTC 与训练延迟

动作专家固定处理 50 个动作 token，即一个长度为 50 的动作块。flow matching 的时间步通过 adaptive RMSNorm 注入。为模拟真实推理延迟，训练时随机加入 0–12 个时间步的延迟；在 50 Hz 控制频率下，最大延迟约 240 ms。作者还使用训练时版本的实时动作分块（RTC），使相邻动作块在推理延迟存在时仍保持平滑。

###### D. 子目标图像训练

真实未来图像的采样方式为：约 25% 概率取片段末尾图像，约 75% 概率从当前时刻之后 0–4 秒均匀采样。为了缩小真实图像和生成图像之间的训练/测试差异，额外加入世界模型生成的子目标图像作为训练样本。

##### VII. 运行时 Prompt 与算法

运行时每个任务至少提供控制模式和 episode 元数据。默认元数据策略是：

- 速度取该任务 episode 长度的第 15 百分位；
- 质量固定为 5；
- 错误固定为 false。

子任务由高层策略或人类 supervisor 给出。若启用子目标图像，在子任务变化时立即刷新，或每经过 $\Delta=4$ 秒刷新一次，以先发生者为准。世界模型和 VLA 异步运行，主策略持续使用当前最新可用的子目标。

算法 1 的中文流程如下：

1. 输入初始观察 $o_0$、总体任务 $\ell$、元数据 $m$ 和控制模式 $c$。
2. 从高层策略或人工 coaching 初始化子任务 $\hat{\ell}$。
3. 采样子目标图像 $g^\star\sim p_\psi(g^\star\mid o_0,\hat{\ell},m)$。
4. 组装上下文 $C=\{\ell,\hat{\ell},g^\star,m,c\}$。
5. 根据历史观察和上下文采样 50 步动作块。
6. 循环执行：若子任务改变或 4 秒计时器到期，异步生成新的子目标；每执行 $\hat H\in\{15,25\}$ 步后重新推理；执行新动作块的当前动作。

所有实验使用 5 步动作去噪，并从 50 步动作块中执行 15 或 25 步。由于 prompt 组件做了 dropout，推理还可以使用 classifier-free guidance（CFG）对某一部分上下文施加引导。论文主要对 episode 元数据做 CFG，使用权重 $\beta\in\{1.3,1.7,2.2\}$，例如引导策略朝更快的执行模式移动。

##### VIII. 机器人系统

图 4 所示平台及其可读标注包括：

- **Mobile Manipulators / 移动操作机器人**：双臂，每臂 6 DoF；1 DoF 夹爪；1–2 DoF 升降机构；3 DoF 全向底盘。
- **Static Bimanual Robot / 静态双臂机器人**：两条 6 DoF 手臂、1 DoF 夹爪。
- **Bimanual UR5e / 双臂 UR5e**：两条 6 DoF 手臂、1 DoF 夹爪。
- **Single-Arm Robots / 单臂机器人**：6 DoF 手臂、1 DoF 夹爪。

UR5e 运行在 20 Hz，其他机器人运行在 50 Hz。各机器人有前视相机和左右腕部相机，移动平台另有后视相机。动作通过简单 PD 控制器执行；若采用末端执行器控制，则用数值逆运动学把末端目标转换为关节目标。

##### IX. 实验评估

###### A. 开箱即用的灵巧任务

论文把 π0.7 与 π0.6* 的 RL 专家、π0.6 上的 SFT 专家以及去掉元数据/自主评测数据的消融模型比较。任务包括：叠短裤和 T 恤、叠最难的衬衫、制作浓缩咖啡、折叠盒子、做花生酱三明治、把 T 恤翻面、穿过自动关闭的门、切西葫芦、削水果蔬菜、替换垃圾袋等。

主结论是：同一个 π0.7 在这些任务上能达到接近任务专用策略的表现，且在多样衣物折叠和折箱任务上吞吐率高于 RL 专家。去掉 episode 元数据或不加入自主评测数据都会使性能下降，吞吐率差距尤其明显。

###### B. 语言指令跟随

测试覆盖 4 个未见厨房和 2 个未见卧室，共 14 个场景，每个场景需要执行 3–6 步开放式指令。任务包括重新摆放物体、整理物品、操作家具和清理洒出液体。π0.7 的总体指令跟随成功率明显高于 π0.5 和 π0.6。

复杂指代实验把普通命令与不常见命令对照，例如“拿起葡萄”与“拿起最大盘子上的水果”，或者“拿起我用来喝汤的物体”。π0.7 在复杂指代上优于旧模型；加入生成子目标图像后进一步提升，说明世界模型的图像能把语言语义转换成更具体的视觉目标。

为检验模型是否真正读取指令而不是复制数据偏置，作者构造 Reverse Bussing 和 Reverse Fridge to Microwave：把垃圾和餐具放入与训练中相反的容器，或把食物从微波炉移回冰箱。π0.7 更能突破这些强数据偏置；逆向冰箱任务中，生成子目标图像对成功尤其关键。

###### C. 跨本体迁移

实验逐步增大源机器人与目标机器人的差异：

1. 多种机器人都收集过数据的 Table Setting，目标为静态双臂机器人；
2. 从较大的双臂 UR5e 迁移到较小的静态双臂平台，任务为 Bag In Backpack 和 Organize Tupperware；
3. 从较小的静态双臂平台迁移到单臂 UR5e，任务为 Shirt Bagging；
4. 从较小静态双臂平台迁移毛巾和 T 恤折叠到更大、更重的双臂 UR5e。

π0.7 在最大本体差异的 Shirt Bagging 上明显超过旧模型；在毛巾和 T 恤折叠上也能零样本迁移，并且加入世界模型生成的视觉子目标后继续提升。图 13 展示的不是简单复刻源机器人动作：源平台把袋子撑开后用另一只手插入，UR5e 则利用更大的可达范围采用单臂抓取放入；源平台折衣服时常用倾斜末端压住布料，UR5e 则采用更适合其运动学的垂直抓取。

###### D. 组合式新任务

短时程新任务不一定需要专门数据。论文报告模型能直接尝试压下法压壶、把米舀入电饭煲、用布擦拭尺子和耳机、旋转齿轮组或桌面风扇等任务。

更长的空气炸锅、倒出空气炸锅食物和烤百吉饼任务不能只靠一句总体指令稳定完成。作者让人类用逐步语言 coaching，例如“用左手抓住空气炸锅把手”“拿起红薯”“把红薯放入空气炸锅”“关上空气炸锅”。π0.7 能在完全未见任务和环境中跟随这些指令；再把 coaching 轨迹用于训练高层策略后，可以得到自主版本，而且性能接近人工 coaching 版本，不需额外收集低层动作示范。

###### E. 多样、混合质量数据是否有效

作者在“叠短裤和 T 恤”上按质量和速度切出前 30%、前 50%、前 80% 及全部数据，并分别训练带/不带 episode 元数据的模型。没有元数据时，加入更多低质量数据可能使性能下降；有元数据时，数据量增加即使平均质量下降，性能仍持续改善。作者把这解释为元数据帮助模型区分不同策略和质量，并在测试时选择目标行为。

另一组消融移除任务多样性最高的 20% 数据，或随机移除 20% 数据。两者训练数据量相同，但去掉最高多样性数据的模型在所有短时程新任务上明显更差，说明任务多样性本身为组合式泛化提供了有效组成。

##### X. 讨论与限制

论文的总体结论是：丰富上下文和更大、更异质的数据可以让一个通用模型表示不同质量和策略，并把专家能力蒸馏到单一 π0.7 中。模型表现出的能力包括复杂语言跟随、跨机器人迁移、按目标本体改变策略、以及把既有技能重新组合。

同时，作者明确承认：已见任务成功率常超过 90%，但未见任务或未见任务-本体组合通常在 60–80% 范围；生成子目标图像需要昂贵的 14B 世界模型；在超大、超多样数据中，很难证明一个任务“真正从未出现”，因为相关技能可能以不同标签或其他任务的附带行为出现在训练数据里。因此“组合式泛化”可能同时包含真正的新组合和跨情境重混已有技能。

### 数学与数据流总结

```text
历史观察 o_{t-T:t}
  ├─ 多视角图像 + 历史帧 ──> MEM 视觉编码器 ──> 固定数量视觉 token
  ├─ 本体状态 q_{t-T:t} ──> 线性投影 ──> 状态 token
  └─ 总体任务 ℓ、子任务 ℓ̂、元数据 m、控制模式 c、子目标 g
                         ↓
              Gemma3 4B VLM backbone
                         ↓ 读取 VLM 激活
              860M flow-matching action expert
                         ↓
              50 步连续动作块 a_{t:t+49}
                         ↓ 执行 15 或 25 步，再闭环重规划
```

- 物理机器人自由度、图像 token 数、VLM 隐藏宽度、动作 token 数是不同概念，不能互相等同。
- 50 个动作 token 表示时间块长度；每个 token 的连续向量维度由控制模式和机器人动作空间决定。
- `FAST tokens` 主要用于训练 VLM 主干；`flow actions` 由动作专家用于连续动作生成；两者在图 19 所示注意力结构中不互相读取。

#### 附录 A：贡献类别

#### 附录 B：注意力模式

无图像目标时，π0.7 使用类似 π0.5 的结构：记忆相关图像视图的 embedding 在块内全局双向注意；FAST token 只在训练中出现，flow action 与 FAST 不互相读取。有图像目标时，图像目标作为文本 prompt 之后的 block-causal 双向块。CFG 推理把正负条件打包成两条互不读取的分支。这个结构保证上下文可以被动作读取，同时避免不同输出分支之间发生非目标信息泄漏。

#### 附录 C：世界模型训练

世界模型从 BAGEL 初始化，使用高质量分段语言标签的机器人数据和人类第一视角视频，并混合图像编辑与视频数据。每个样本包含子任务指令、3 个相机输入和片段末尾的 3 个目标图像。相机输入同时经过 ViT 和 VAE：ViT 负责语义理解，VAE 负责细节生成。ViT 输入分辨率为 $448\times336$，VAE 输入（包括目标图像）为 $512\times384$；差异来自 14 和 16 的 patch size。测试时每 4 秒刷新子目标图像。

#### 附录 D：推理速度与优化

π0.7 和高层策略使用单张 NVIDIA H100。最小配置在 3 个相机输入、5 步动作去噪、训练时 RTC 下约 38 ms。启用 MEM 历史编码器和子目标图像后，最坏情况约 127 ms。世界模型生成目标图像较昂贵：使用 4 路张量并行的 4×H100、大矩阵乘法 8-bit 量化、修改版 SageAttention，可用 25 步去噪在约 1.25 s 生成图像；其序列长度接近 10,000 token。

#### 附录 E：跨本体动作空间比较

对多个跨本体任务比较 joint 和 EE 控制，未观察到 EE 的稳定优势，因此主实验采用 joint 便于解释。

#### 附录 F：人类 T 恤折叠研究

招募 10 名高经验操作员，每人 3 次，共 30 次试验；没有练习或热身。目标机器人为此前未用于该任务的双臂 UR5e，时间限制、初始平铺状态和评分标准与 π0.7 实验相同。人类平均任务进度 90.9%、成功率 80.6%；π0.7（GC）为 85.6%、80%。

### 术语表

| 术语 | 原文 | 简明解释 |
|---|---|---|
| VLA | Vision-Language-Action | 将视觉、语言和机器人动作放在同一策略中的模型 |
| VLM | Vision-Language Model | 视觉-语言模型，π0.7 的语义主干 |
| MEM | Multi-scale Embodied Memory | 对多时间尺度机器人视觉历史做压缩和编码的记忆模块 |
| action expert | action expert | 读取 VLM 激活并用 flow matching 生成连续动作的较小 Transformer |
| subtask instruction | subtask instruction | 当前下一阶段的语义指令 |
| subgoal image | subgoal image | 描述任务成功推进后近未来场景的图像目标 |
| episode metadata | episode metadata | 对轨迹速度、质量和错误的上下文标记 |
| compositional generalization | compositional generalization | 将已有技能以训练中未出现的组合用于新任务 |
| cross-embodiment transfer | cross-embodiment transfer | 把一个机器人本体上的能力迁移到另一个本体 |
| RTC | real-time action chunking | 训练和推理中处理动作块延迟、保持轨迹平滑的方法 |
| CFG | classifier-free guidance | 用有条件/无条件分支引导生成动作的推理方法 |
| KI | knowledge insulation | 让动作专家读取 VLM 激活但不把梯度传回 VLM 的训练配方 |
| GC | generated conditioning | 使用世界模型生成的子目标图像作为条件 |
