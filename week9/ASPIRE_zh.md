## 摘要

传统机器人编程极具挑战性：它需要协调多模态感知、处理复杂的物理接触动力学，并应对多样化的环境配置与执行失败。本研究提出 ASPIRE（通过迭代机器人探索实现智能体技能编程，Agentic Skill Programming through Iterative Robot Exploration），这是一个面向机器人学的持续学习系统，能够在「代码即策略」（code-as-policy）范式下自主编写并优化机器人控制程序，同时将经验累积沉淀为可复用的技能库。ASPIRE 实现了可复用技能的自动化发现，这些技能能够在多个任务、仿真与真实世界环境以及不同的机器人具身形态之间持久发挥作用。ASPIRE 并非依赖固定的人工工程化流水线，而是在开放式学习循环中运行，该循环由三个核心组件构成：

闭环机器人执行引擎，该引擎提供细粒度的逐基元多模态轨迹（例如感知叠加图、抓取候选、运动轨迹与碰撞反馈），使智能体能够自主诊断失败、综合修复方案并验证结果；持续扩展的技能库，将经过验证的修复方案提炼为模组化、可迁移的机器人知识；演化搜索过程，生成多样化的任务序列与控制程序，并系统性地进行调试，以探索超出单一轨迹优化的广泛解空间。

随著 ASPIRE 接触更多任务，其不断增长的技能库能够实现愈发快速的适应。实验结果表明，ASPIRE 在扰动下的操作任务（LIBERO-Pro）上超越现有方法高达 77%，在 Robosuite 的双臂交接任务上提升 72%，在长时程家庭任务（BEHAVIOR-1K）上最高提升 32%。积累的技能库进一步实现了强大的零样本泛化能力：在具代表性的未知长时程任务（LIBERO-Pro Long）上，ASPIRE 达到了 31% 的成功率，显著优于现有方法 4% 的成功率（尽管后者高度依赖测试时推理与重试）。最后，在仿真中发现的技能为仿真到真实世界（sim-to-real）迁移提供了初步证据，尽管具身形态与机器人 API 存在差异，仍显著减少了真实机器人的编程开销。

## 1. 引言

软件工程智能体领域的最新进展表明，语言模型能够自主检查执行轨迹、定位故障、修订代码实现，并通过与执行环境的反复交互实现自我改进。在机器人领域，该范式启发了「代码即策略」（code-as-policy）系统的发展，这类系统将感知模组、规划 API 与控制基元组合成可执行的机器人程序。由于机器人行为被显式表示为程序，因此原则上可以通过交互反馈对其进行检查、编辑、调试与完善。

然而，现有的机器人编码智能体本质上受到简陋执行环境的严重限制，这些环境仅提供粗粒度的任务级反馈。调试机器人程序具有内在的挑战性，因为失败可能源于诸多相互关联的组件，包括多模态感知、运动规划、抓取生成、接触动力学以及长时程任务协调。一次失败的演练轨迹可能仅仅表明任务未成功，却无法说明根本原因是感知错误、不稳定的抓取、规划异常，还是下游恢复机制的失效。如果缺乏细粒度的诊断轨迹，智能体便难以确定应当检查哪些依据、如何定位故障，以及应当尝试何种修复策略。

此外，现有系统无法跨任务积累经验。一旦任务完成，探索出的修复方案与恢复策略就会被抛弃，而不是整合为可复用的技能。这导致智能体在解决第一百个任务时，其经验水准实际上与解决第一个任务时无异。

人类机器人工程师的工作方式则截然不同。当机器人程序执行失败时，工程师会重放执行过程，检查感知输出与运动轨迹，定位发生故障的子系统，修改实现方案，并将可复用的恢复策略内化为自身经验。随著时间推移，调试经验会转化为可迁移的知识，包括抓取恢复启发式、导航策略、提示词构建方法以及能够跨任务泛化的流程性修复机制。这种可复用知识的持续积累，正是人类机器人程序员效率随时间推移愈发高效的核心原因。

在本研究中，研究团队提出了 ASPIRE，这是一个具备自我改进能力的机器人持续学习系统，能够在代码即策略范式下自主编写并优化机器人控制程序，同时将经验沉淀至可复用的技能库中。ASPIRE 并非在固定的「感知-规划-执行」流水线中运行，而是在开放式学习循环中运作；在此循环中，智能体能够自行决定如何检查执行轨迹、诊断失败、综合修复措施、验证修正后的行为，并将成功的恢复模式沉淀为可跨任务迁移的持久技能。

第一，闭环机器人执行引擎取代了粗粒度的试验级反馈，提供逐基元的执行轨迹。对于每次感知、规划、抓取与控制调用，执行引擎都会记录观测、输入、输出以及可用的视觉依据。这些丰富的多模态轨迹使智能体能够选择性检查显著的基元日志，逐步定位故障，并通过重新执行来验证修复。

第二，ASPIRE 维护一个不断扩展的技能库，将经过验证的修复提炼为模组化、可迁移的机器人知识，可在后续任务中作为上下文指引（in-context guidance）进行检索。

第三，ASPIRE 采用演化搜索过程生成多样化的任务序列与控制程序，通过迭代调试与并行优化，将探索范围拓展到单轨迹自我改进之外。

这些组件共同构成了一个性能随经验增长而扩展的自我改进机器人系统：ASPIRE 接触的任务越多，其技能库规模越大，向新任务、更长时程行为以及在不同具身形态下出现相似故障-恢复模式的真实世界环境的迁移能力就越强。

在实验评估中，ASPIRE 在多种短时程与长时程机器人基准测试上均展现出强大的自我改进能力。相较于现有编码智能体，ASPIRE 在 LIBERO-Pro 扰动基准套装上的成功率提升了高达 77 个百分点，在 Robosuite 富接触操作任务上提升了高达 72 个百分点，在具有程序化生成布局的 BEHAVIOR-1K 长时程家庭任务上提升了高达 32 个百分点。基于在 LIBERO-90 上积累的技能库，ASPIRE 能够零样本迁移至 LIBERO-Pro Long，取得 31% 的成功率，而现有方法尽管高度依赖测试时推理与重试，其成功率仍停留在 4%。研究团队进一步在真实双臂机器人上评估了在仿真中发现的三项技能，结果表明，检索仿真中学到的技能作为上下文指引能够减少真实世界的推理 Token 开销，并在未经技能迁移而完全调试失败的场景中成功生成可行的控制程序。

## 2. 方法

ASPIRE 由三个组件构成，共同形成开放式学习循环：(1) 机器人执行引擎（第 2.1 节），提供用于故障归因的逐基元多模态轨迹，并执行智能体编写的修复方案以进行闭环验证；(2) 技能库（第 2.2 节），将验证通过的修复累积为可复用技能；(3) 演化搜索过程（第 2.3 节），拓宽超出单轨迹修复的探索空间。随著 ASPIRE 接触更多任务，其技能库持续扩充，使未来任务能够继承已积累的修复方案与可复用策略。

如图 1 所示，ASPIRE 采用协调器-执行者架构。中央协调器管理共享技能库并向各个任务指派执行者编码智能体，而每个执行者在机器人执行引擎中编写、执行、诊断并修复机器人程序。执行者之间不直接交换完整的对话历史或原始试验轨迹。相反，可迁移经验被提炼进技能库中，从而使每个执行者的上下文窗口能够专注于任务规范、当前程序以及与当前失败相关联的结构化执行轨迹。

### 2.1 机器人执行引擎

具身编码智能体需要执行依据来调试机器人程序。先前的方法通过固定的人工设计接口展示此类依据，通常表现为人工策划的场景级摘要或一组预定义的观测值。这导致了权衡两难：反馈过少可能会隐藏发生故障的基元，而过多原始视觉上下文则可能分散智能体的注意力，干扰其对导致故障的因果链条的分析。

ASPIRE 将这种固定的反馈通道转变为开放式的调试环境。机器人执行引擎记录感知、规划和控制调用的逐基元多模态轨迹，将轨迹呈现给编码智能体，并执行智能体编写的修复方案以进行闭环验证。对于每个基元调用，轨迹中记录了所调用的 API、输入与输出、返回状态以及相关的多模态依据，例如 RGB 关键帧、叠加标记图、抓取候选、物体位姿以及运动规划结果。智能体不会接收完整的视频帧；引擎仅保留每个基元调用紧前与紧后的帧，以及对应的叠加图和返回值，从而使智能体能够专注于与失败相关联的调用周围的证据。

图 2 详细展示了 BEHAVIOR-1K 中「导航并拾取收音机」（NAVIGATE-AND-PICK-UP-RADIO）任务的一个调试过程。第一人称视角关键帧显示机器人找到了收音机，但屡次尝试接近失败，随后在调整接近方向后成功接近。基元轨迹定位了故障原因：感知环节成功并返回了收音机的位姿，但多次调用均返回。通过检查导航返回值及相关日志，智能体发现生成的导航目标距离桌子边界过近（约在桌子边缘 20 厘米以内）。这触发了避障机制，导致规划器报错。因此，失败并非由检测或抓取收音机引起，而是因为目标位姿在桌子碰撞约束下不可行。

修复方案直接源于该诊断。智能体并未修改感知提示词或抓取基元，而是编写了一个多角度接近常规程序（multi-angle approach routine），围绕收音机采样替代导航目标，并执行能够避开碰撞缓冲区的接近方向。执行引擎展示了证据，验证了修补后的程序，并赋予智能体分析日志、形成假设并做出针对性修复决策的能力。

### 2.2 技能库

程序错误会在不同任务间重现，但可复用的知识极少是完整的任务程序。ASPIRE 的技能库存储异构的修复知识：定位启发式、感知提示词、抓取约束、导航恢复策略、运动基元、场景理解常规流程以及调试工作流。本研究未预先设定分类体系，技能是从验证通过的修复中归纳而来的：编码智能体从执行轨迹中诊断故障，修补程序，在调试配置上验证修复，协调器仅将具备复用性的模式纳入共享技能库。

每项技能都以精炼的上下文指引形式存储，包含失败特征、适用条件、修复策略，以及在必要时提供的代表性代码草图。图 3 展示了代表性条目及技能库的广泛覆盖范围。对于图 2 中的收音机任务，录入的技能是导航恢复模式而非完整的拾取收音机程序：当因采样目标位姿落入碰撞缓冲区而在障碍物边界附近反复出现规划器错误时，在重试感知和抓取前先围绕物体采样替代接近方向。这种表示方式允许未来的执行者直接重用已验证的修复，而无需在测试时通过推理重新摸索，同时支持对更复杂仿真任务的零样本迁移，并为选定的仿真技能提供跨具身形态泛化至真实机器人的机制。

执行者提交结构化报告，总结失败模式、已验证修复及潜在可迁移的修复模式。协调器审核这些报告，验证其是否符合允许的 API 规范，并仅将通过调试验证的可复用修复提升至共享技能库中。附录 E.1 提供执行者汇报和协调器技能准入的具体提示词。

### 2.3 演化搜索

单纯依赖轨迹引导的调试可能会陷入局部修复循环，即智能体反复修补同一个失败的策略，而未能探索从根本上解决任务的不同路径。ASPIRE 采用演化搜索拓宽对可执行机器人程序的探索空间，鼓励多样化的修复假设与任务策略。

在每一轮中，编码智能体基于技能库，以历史表现最佳的程序及前期评估中的失败轨迹为条件，提出包含K个候选程序的群体。每个候选程序在机器人执行引擎中运行，产生任务结果与新的诊断轨迹。下一轮搜索则以表现最佳的程序及其残余失败模式为条件，从而使搜索能够探索不同的策略，而非重复优化同一解。

搜索目标是机器人程序本身。候选者通过闭环执行进行筛选，验证通过的修复在搜索结束后纳入技能库（前提是其能跨环境变量与任务泛化）。当候选程序解决了调试配置或耗尽搜索预算时，搜索终止。算法 1 总结了演化搜索流程。详细流水线见附录 E.4。

## 3. 实验

### 3.1 实验设置

在所有仿真基准测试中，均使用配备 1M Token 上下文窗口的 Claude Code（搭配 Claude Opus 4.6）作为编码智能体。智能体在 CaP-X 框架中编写可执行的 Python 机器人程序，该框架是构建于 MuJoCo Playground 之上的开源代码即策略框架，提供用于感知、几何与运动规划的机器人编程 API。智能体、环境与 API 集在所有实验中保持固定。

在真实机器人技能迁移研究（第 3.6 节）中，使用 OpenAI Codex GPT-5.5 的 reasoning-xhigh 模式，部署于双臂 YAM 操作工作站。研究选取了 ASPIRE 在基于 Franka 的仿真中编译的三项技能：易拉罐抓取、碗置于盘上以及抽屉推/拉。这些技能作为上下文指引提供给真实机器人编码智能体。真实机器人环境具有不同的具身形态与 API，但同样提供 ASPIRE 多模态执行轨迹，使智能体能够在调试过程中自主运行、检查并调试程序，而无需特定任务的人工引导。实验对比了包含与不包含仿真技能时的运行情况，测量首次成功所需的 Token 数以及保留测试集的成功率。

### 3.2 基准测试与基准线

评估涵盖三个基准系列：LIBERO-Pro 用于测试对象、目标和空间扰动下的短时程鲁棒性；Robosuite 聚焦於单臂与双臂富接触操作；BEHAVIOR-1K 测试长时程家庭移动操作，包含「导航并拾取易拉罐」与「导航并拾取收音机」。主要编码智能体基准线为 CaP-Agent0，该基准线使用视觉差异比对、预定义技能库与单次测试重试。此外还对比了端到端视觉-语言-动作（VLA）策略，包括 OpenVLA、π"0"和π"0.5"。零样本迁移方面，使用在 LIBERO-90 上积累的技能库评估保留的 LIBERO-Pro Long 任务。

### 3.3 评估协议

在所有基准测试中，环境种子固定了每个任务实例，包括物体位姿、干扰项及初始状态。调试种子与评估种子严格隔离：ASPIRE 在小型调试集上学习，随后在较大的保留评估种子上报告单个程序的成功率；而 CaP-Agent0 在每个种子上重新生成程序并进行重试。BEHAVIOR-1K 评估中，ASPIRE 采用增量代码块执行方式，根据当前多模态轨迹生成下一代码块。

### 3.6 跨具身形态的真实机器人技能迁移

评估在仿真中学习到的技能是否能减少具有不同具身形态的真实机器人上的调试开销。这种迁移并非直接的策略部署：真实机器人使用自身的感知、校准和控制栈，编码智能体仍需通过真实世界执行反馈来调整程序。核心问题在于检索仿真中发现的技能能否提供有用的上下文指引，从而减少达成成功程序所需的真实世界调试量。

表 1 显示，迁移的技能持续降低了调试成本，而对最终成功率的影响则取决于任务特性。放碗任务在两种设置下均取得成功，但检索技能时使用的 Token 显著减少；易拉罐抓取成功率从 13/20 提升至 19/20，总 Token 开销降低了近一个数量级；抽屉操作在技能指引下达到了 11/20 的成功率，而无技能基准线在耗尽更多 Token 预算后仍未产生成功的评估程序。这些结果表明，源于故障的选定技能能够跨具身形态与 API 变更指导真实机器人程序合成，而非仅仅记住特定于仿真器的代码。

### 3.7 消融实验

机器人执行引擎与演化搜索两大组件在 LIBERO-Pro 上进行了严格的消融验证。执行引擎负责提供密集执行轨迹并验证任务级修复，而演化搜索则在执行引擎调试后进一步探索额外的修复候选。图 6(a) 和图 6(b) 将成功率分解为无任一组件的基础系统、添加执行引擎带来的增益，以及演化搜索带来的额外增益。执行引擎带来了最大的平均提升，将宏观平均成功率从 14% 提升至 62%；演化搜索进一步改善了剩余的困难任务，在具备两个组件时达到了 72%。

图 6(c) 追踪了随著演化搜索预算增加低表现任务的性能变化。在前几轮中成功率稳步提升，表明采样多个修复假设能够迅速找回单次迭代调试遗漏的备选方案。随后曲线增长更为平缓，表明额外的轮次对残余困难案例仍有助益，但收益递减。

## 4. 相关工作

机器人控制领域的研究涵盖端到端视觉-语言-动作（VLA）策略，以及组合感知、规划和控制 API 的可执行程序。软件工程智能体为代码编写提供了类似的「编写-执行-调试」循环。ASPIRE 建立在可执行程序范式之上，但专注于持久的具身改进：智能体自由选择基元级多模态轨迹、编写修复代码、验证并跨任务保留成功经验。

大语言模型智能体已通过开放式记忆、技能库和自演化技能库获得性能提升。其他系统使用大语言模型生成奖励、课程、环境或搜索候选。与仅记录成功的记忆、文本反思或用于下游策略训练的奖励函数不同，ASPIRE 存储从归因的具身故障中提炼出的经验证修复知识。其技能在内容和准入上均保持开放：它们源于智能体自身的调试经验，跨越异构类别（第 2.2 节），并作为上下文指引重新用于未来的程序修复。演化搜索（第 2.3 节）在可复用模式被纳入库之前进一步拓宽了可执行程序修复的空间。

## 5. 局限性

第一，虽然选定的仿真发现技能支持在不同具身形态上进行自主真实机器人调试，但该系统尚未成为完全自主的真实世界终身学习者。与仿真环境中成功检测和场景重置成本低廉且可程序化实现不同，真实世界部署仍需要鲁棒的成功检测、安全重置、安全监控和校准维护。未来的工作应当打通这一评估与重置循环，以将仿真到真实世界的技能迁移扩展至更广泛的真实世界任务套装中。

第二，本方法依赖于冻结的前沿大语言模型（配备 1M Token 上下文窗口的 Claude Opus 4.6）来解释多模态轨迹、编写程序修复并提出演化搜索候选；尚未验证较小或较弱的大语言模型是否能够维持相同的调试循环。

第三，ASPIRE 使用预定义的感知、规划和控制基元 API 编写程序。该 API 使得调试切实可行且安全，但也限制了智能体能够表达的行为空间：如果任务需要暴露基元之外的传感、控制或交互能力，智能体必须低效地逼近它们，或者依赖人工扩展 API。未来的系统应当研究智能体如何安全地提出、验证并整合新的机器人基元。

第四，技能库目前优先考虑经过验证的可复用修复，但尚未完全解决长期记忆管理问题。随著技能库增长，某些条目可能会变得陈旧、过度特定、冗余或对新任务产生误导，这解释了零样本迁移中的非单调趋势。需要更鲁棒的检索、剪枝、排序和重新验证机制来保持技能库在大规模下的实用性。

最后，调试与演化搜索循环属于计算密集型，每个任务消耗大量的大语言模型调用以及仿真器或机器人演练；扩展至超大型任务套装将需要更廉价的大语言模型推理、更高样本效率的搜索，或更强大的前期修复复用机制。

## 6. 结论

本研究提出了 ASPIRE，这是一个面向机器人学的持续学习系统，能够自主编写和优化机器人控制程序，同时将经验累积至可复用的技能库中。ASPIRE 在包含三个组件的开放式学习循环中运行：提供细粒度多模态轨迹的闭环机器人执行引擎、将经验证修复提炼为可迁移知识的持续扩展技能库，以及探索多样化任务序列与控制程序的演化搜索过程。在多样化的基准测试中，ASPIRE 显著优于现有的 VLA 和编码智能体基准线，展示了向未知长时程任务的强大零样本迁移能力，并提供了初步证据表明在仿真中发现的技能能够跨具身形态迁移，在存在不同具身形态和机器人 API 的情况下显著降低真实机器人编程的 Token 成本。
