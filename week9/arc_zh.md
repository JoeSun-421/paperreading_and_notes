## 摘要

当前改进机器人基础模型（robot foundation models，RFM）的主流方法依赖更大的模型、更多的机器人示范以及代价高昂的大规模训练。我们表明，还存在一种有效且高效的互补途径：合适的推理配方能够显著提升现有先进 RFM 的零样本任务性能。我们将这一配方称为 **ARC**。它包含三个关键要素：推理轨迹、可扩展的自动标注流水线，以及使预训练 RFM 学会利用这些轨迹进行控制的适配策略。

首先，我们发现，有效的推理轨迹应当以机器人的下一步动作为基础，并解释动作的因果结构：为什么这个动作合适，以及它应当产生什么效果。其次，我们表明，可以从现有示范中自动生成这类轨迹，因此无需采集新的机器人数据，就能从 DROID 构建 Arc-Trace-DROID。最后，我们展示了 π0.5 等先进视觉-语言-动作模型（VLA）和 Cosmos3-Nano-Policy 等世界动作模型（WAM）如何学习利用这些轨迹进行控制；微调和推理过程会根据各模型的架构与能力进行定制。

使用 ARC 后，在不增加机器人示范、不进行基础模型规模训练的条件下，我们获得了据我们所知前所未有的零样本 RFM 性能提升。适配后的模型在 RoboLab-120 和 MolmoSpaces 上建立了新的最佳结果，在 RoboLab-Reasoning-50 上最高提升 50 个百分点。在真实机器人上，ARC 使 π0.5 的任务成功率提升了 82.2 个百分点。

## 图 1：ARC 总览

ARC-Trace 自动为 DROID 示范重新标注动作基础的因果推理轨迹，生成 Arc-Trace-DROID。随后使用这些监督信号微调 VLA 和 WAM。推理轨迹把动作块与其原因和预期效果连接起来。示范中给出的任务可能是“把杯子放进去”或“拿起水槽里的罐子并把它放进柜子”。例如，对任务“移动芥末瓶，并把它后面的物体放入碗中”，轨迹会依次说明：必须先移动芥末瓶、把它稳妥抓起并移开；瓶子后的物体因此暴露出来；随后在该物体中心形成稳定抓取；最后把物体对准碗口并放入。微调后的模型在困难的推理任务上领先基线。

# 1 引言

通过在大规模示范数据集上进行模仿学习训练，机器人基础模型已经具备了广泛的操作能力。然而，让它们变得更强的主流配方仍然是暴力扩展：增加机器人数据、增大模型，并再次进行基础模型规模的训练。这使得每一次任务成功率的提升都要付出很高代价。问题是：在不修改架构、不增加新的机器人数据、也不以基础模型规模训练的情况下，如何提升现有 RFM 的性能？

本文研究这个问题。我们具体发现，增加或完善 RFM 的推理能力，是一种有效且高效的改进策略。采用合适的配方后，推理可以显著提升现有先进模型（如 π0.5 和 Cosmos3-Nano-Policy）的性能（见图 1）。据我们所知，这是首次在无需新的机器人示范、也无需基础模型规模训练的情况下，通过某种策略获得如此显著的零样本 RFM 性能提升。我们把这一推理配方称为 **ARC**。

ARC 汇集了三部分：合适的推理内容、可扩展的监督来源，以及让模型学会用推理进行控制的训练过程。

**第一，推理应当包含什么？** 我们发现，控制推理应当是因果的：它要解释为什么当前情况下某个动作合适、该动作应当产生什么效果；同时还要以动作为基础，明确机器人应该采取的具体步骤，从而实现该效果。为此，我们提出“动作基础的因果轨迹”（action-grounded causal traces），把当前真实状态、机器人下一步应该做什么，以及动作完成后应当变成什么状态连接起来。

**第二，如何大规模获得监督？** 机器人示范通常记录观察和动作，却省略了每个决策背后的推理。因此，动作基础推理无法直接从现有数据集中获得。我们提出一种自动给示范添加因果轨迹的方法，使轨迹与动作块对齐，并用它重新标注 DROID，构造 Arc-Trace-DROID。

**第三，如何让模型利用推理进行控制？** 我们展示了如何微调 RFM，使其根据推理轨迹来决定行为，同时保留原有的控制能力。不同模型使用相同的推理轨迹和训练数据，但微调与推理过程会针对各自架构和能力进行调整。

我们在两个有代表性的先进 RFM 上评估该配方：作为 WAM 的 Cosmos3-Nano-Policy，以及作为 VLA 的 π0.5。在 RoboLab-120 的三种设置下，ARC 都能提升两个模型，适配后的模型在每种设置中均排名第一或第二。在 MolmoSpaces 上，π0.5 和 Cosmos3-Nano-Policy 的任务成功率分别提升 27.2 和 18.6 个百分点。这些结果在 RoboLab-120 和 MolmoSpaces 上建立了新的最佳水平。在侧重推理的 RoboLab-Reasoning-50 上，π0.5 和 Cosmos3-Nano-Policy 的任务成功率分别提升 46.8 和 50.0 个百分点。在真实世界执行中，这些提升仍然存在，推理和长时程任务提升了 82.2 个百分点。

在所有评估中，经过 ARC 训练的模型都更可靠地完成以下行为：遵循信息不完整的指令、推断缺失步骤、完成长时程任务、适应环境变化以及从错误中恢复。

我们进一步量化配方中不同组件的贡献。结果显示，只增加中间语言而不采用正确结构，提升有限；更大的收益来自将因果推理内容与动作基础训练过程结合起来。作为副作用，该配方还提高了训练和推理效率：Cosmos3-Nano-Policy 只需基线约 1/4.3 的训练更新次数就能达到基线成功率；π0.5 和 Cosmos3-Nano-Policy 在推理时分别只需原策略 1/10 和 1/2 的去噪步数，就能达到相当性能。

## 贡献

本文提出 ARC，一种向预训练 RFM 注入推理能力的配方，包含四项贡献：

1. 确定动作基础的因果轨迹是机器人推理的一种中间表示。
2. 提出 ARC-Trace 标注流水线，生成与动作块对齐的动作基础因果轨迹，并据此重新标注 DROID，构建 Arc-Trace-DROID。
3. 提出使预训练模型学会利用推理进行控制的适配策略，并展示如何针对不同模型架构定制微调和推理过程。
4. 在仿真和真实机器人基准上验证 ARC，包括 Cosmos3-Nano-Policy 和 π0.5，证明在无需额外机器人示范、无需基础模型规模训练的情况下，可以大幅提升零样本任务性能。

# 2 相关工作

## 机器人基础模型

研究者已经通过跨任务、跨机器人形态学习，构建了通用机器人策略；也有工作把预训练的视觉和语言知识迁移到动作预测中。视频预训练模型和世界动作模型还进一步学习环境在执行过程中的演化。本文建立在这些预训练控制器之上，研究如何利用已经存在的机器人示范，通过推理监督改进它们的性能。

## 基础模型中的推理

推理允许预训练模型在给出最终答案之前，先经过中间决策。已有工作通过考虑备选方案、使用工具和反馈，以及从中间监督中学习来改进这一过程。在机器人领域，这些思路主要有两种相关用法：一是决定机器人应该执行哪些步骤；二是训练策略去推理它所预测的动作。

第一类方法包括：选择可用技能来完成指令；生成组合感知与控制的程序；根据观察和执行反馈修订计划。第二类方法使用推理标注，教策略哪些信息对动作预测有用。这两类方法都能让机器人受益于示范动作之外的知识，但前提是控制器能够理解所接收的指导。近期工作通过更丰富的引导命令和视觉定位的分层控制来解决这一要求。

## 推理模态

表达机器人控制所需中间决策的方式有多种。空间表示通过图像特征、动作图或体素表示交互位置；关键点和几何约束描述机器人应该在物体之间建立的关系；基于运动的表示通过轨迹草图和视觉轨迹提供指导；预测表示则通过未来预测说明场景应如何演化。

这些方法为控制器提供了明确的空间或时间目标。它们与控制的连接方式取决于具体表示：几何约束可以通过运动优化求解，深度和轨迹预测可以编码为中间 token，视觉轨迹可以通过已有图像输入提供。虽然这些方法展示了结构化指导的价值，但本文关注的是一种可以在不同 RFM 之间共享、且无需额外修改架构的推理监督。

自然语言提供了这种可能性，因为它可以描述任务条件、空间关系和预期结果，而不必绑定到某一套机器人坐标。许多机器人基础模型的预训练 tokenizer 和语言组件已经支持自然语言，其标注还可以从已有示范中自动生成。已有研究使用自然语言描述细粒度运动、传达当前语义子任务，或在预测动作之前推理计划、物体和机器人状态。这些方法说明，语言可以提供有用的中间监督。

# 3 预备知识与问题定义

## 机器人任务设置

我们考虑机器人在部分可观测环境中运行的情况。任务由指令 (g\in\mathcal G) 指定。机器人在时刻 (t) 接收观察 (o_t\in\mathcal O)，并执行动作 (a_t\in\mathcal A)。交互历史记为

\[
h_t=(o_0,a_0,\ldots,a_{t-1},o_t).
\]

为覆盖一次预测多个动作的模型，令

\[
a_t=(a_t,\ldots,a_{t+H-1})
\]

表示长度为 (H) 的动作块。机器人示范是一条轨迹

\[
\tau=(g,o_0,a_0,\ldots,o_T),
\]

训练数据集为

\[
\mathcal D=\{\tau_i\}_{i=1}^{N}.
\]

我们不依赖预训练机器人基础模型的内部架构。每个时间步上，模型定义条件动作分布

\[
\pi_{\theta_0}(a_t\mid h_t,g),
\]

其中 \(\theta_0\) 是预训练参数。令 \(S(\tau,g)\in[0,1]\) 衡量轨迹是否完成任务，则策略目标是最大化

\[
J(\pi)=\mathbb E_{g,\tau\sim\pi}[S(\tau,g)].
\]

## 将推理视为中间计算

标准策略直接根据任务和交互历史预测动作。更一般地，我们把推理定义为：在动作预测之前形成一个中间表示 \(r_t\in\mathcal R\)，该表示携带与当前决策相关的信息：

\[
r_t\sim q_\phi(r_t\mid h_t,g),\qquad
 a_t\sim\pi_\theta(a_t\mid h_t,g,r_t).
\]

因此得到的动作分布为

\[
\pi_{\theta,\phi}(a_t\mid h_t,g)
=\int \pi_\theta(a_t\mid h_t,g,r_t)q_\phi(r_t\mid h_t,g)\,dr_t.
\]

## 问题定义

给定一个预训练机器人基础模型 \(\pi_{\theta_0}\) 和一个只含观察、动作而没有推理监督的示范数据集 \(\mathcal D\)，我们的目标是学习一个有推理的策略 \(\pi_{\theta,\phi}\)，提升任务成功率，同时保留模型原有控制能力。关键约束是：不需要新的模型架构、不需要新的基础模型规模预训练阶段，也不需要收集另一个大型机器人数据集。

# 4 ARC 框架

ARC 包含三个组件：推理表示（第 4.1 节）、ARC-Trace 重标注流水线（第 4.2 节），以及把推理连接到控制的微调配方（第 4.3 节）。

## 4.1 动作基础的因果推理

我们用自然语言表示 \(r_t\)，复用模型原有的语言条件能力。我们考察 ECoT 风格推理和语义子任务监督，并把两者适配到相同的 π0.5 主干上分别进行微调。

为了判断这些表示是否真正影响动作预测，我们检查动作专家对图像 token 和自然语言 token 的注意力分布。在子任务监督和具身 CoT 下，动作专家仍然主要关注视觉观察，对中间语言的注意力很少。作为诊断而不是因果证明，这一模式暴露出一种合理的捷径：模型可以从相同的图像和指令中同时预测计划、物体列表、运动方向和子任务标签，在满足语言目标的同时继续只依赖视觉来预测动作。这与其他机器人基础模型中报告的“指令改变但控制器仍追逐原目标”的接地失败一致。

因此，缺失的信息既不是更长的场景描述，也不是更细的任务分解。动作之所以被选择，是因为它预期会在世界中产生某种变化；推理应当明确表达这种关系。基于这一原则，我们开发了面向机器人控制的动作基础因果表示。

对于动作块 \(a_t\)，ARC-Trace 把推理表示为

\[
r_t=[\text{State},\text{Cause},\text{Consequence},\text{Effect},\text{Action},\text{Avoid},\text{Completion}]_t.
\]

- **State（状态）**和 **Cause（原因）**：确定当前步骤与任务相关的事实，并说明这些事实为何重要。
- **Consequence（后果）**：从这些事实出发向前推理可能发生什么。
- **Effect（效果）**：选择能够推进任务的状态变化。
- **Action（动作）**：把该效果连接到即将执行的动作块。
- **Avoid（规避）**：记录不希望出现的变化。
- **Completion（完成度）**：在连续决策之间维护任务进度。

我们称之为“动作基础的因果推理轨迹”，因为它通过说明动作想要造成的效果来解释动作，而不是孤立地描述动作。

同一主干模型使用 ARC 轨迹训练后，动作专家会明显增加对自然语言推理的注意力，尤其关注把当前状态、预期效果和最终动作连接起来的片段。这本身不能证明模型在行为上依赖轨迹，但表明轨迹携带了动作专家实际使用的信息，而不再只是一个冗余的辅助目标。第 5 节将考察这种变化如何影响任务性能。

**图 2 示例。** 任务是“把笔从杯子里取出并放到桌上”。子任务监督只写“抓住杯中的笔”；具身 CoT 给出“抓住笔、把它从杯中提起、移到桌面上并释放”，并列出绿色笔、白色杯子和纸张。ARC 轨迹则进一步解释：白色杯子在画面偏右，绿色笔立在杯口中；笔仍被杯子支撑，因此必须先稳固抓取再取出。预期效果是在笔杆暴露处形成稳定居中的抓握；机器人应夹住笔杆较低且可见的部分，确认稳定后再抬起；同时避免碰到杯沿或杯壁、撞倒杯子，或在抓取不牢时开始搬运。原图的注意力图报告：腕部相机注意力中，子任务监督为 4%、具身 CoT 为 6%、ARC 为 41%；图中颜色条表示注意力由低到高。

## 4.2 ARC-Trace：大规模推理监督

上述表示带来了监督问题：已有机器人数据集记录机器人做了什么，却没有记录为什么该动作在当时合适。因此，无法直接获得足以训练机器人基础模型规模的动作基础推理。把推理与新的示范一起采集也很昂贵。

我们的关键观察是：恢复这种监督所需的信息，其实已经存在于成功示范中。任务指令说明目标，视频记录场景如何变化，动作序列说明这些变化是如何产生的。现代视觉-语言模型可以提取这种结构，并用自然语言表达出来。因此，我们能够在数据采集后生成推理监督，而无需收集新的机器人轨迹，也无需人工逐个标注动作。

我们据此构建 Arc-Trace-DROID，自动为 DROID 数据集重新添加动作基础因果推理。对每个 episode，首先根据指令和视频生成时间上有定位的任务执行描述；接着生成 episode 专属的状态检查，用于记录跟踪示范进程所需的物体、关系和任务条件。这些检查提供结构化证据，减少最终标注器从单帧观察中推断完整状态的负担；最后，在选定关键帧上，视觉-语言模型结合任务指令、episode 描述、当前观察和状态检查，生成与相应动作块对齐的推理轨迹。

该流程产生约 7.5 万条重新标注的 episode 和 120 万个与动作对齐的帧。完整的标注提示词、采样策略和过滤步骤见附录 A.1。

## 4.3 用于推理引导控制的微调

我们微调预训练模型，使其根据对齐的因果轨迹、观察和任务指令来预测示范动作。轨迹复用基础 tokenizer 和 embedding，并由语言 Transformer 结合任务与视觉上下文处理。动作生成层在整个去噪过程中关注这些表示；token 的位置、投影和 mask 取决于模型架构。

我们保留各模型的 flow matching 目标：VLA 预测动作，WAM 预测动作和未来观察。令 (K) 表示这些模态，目标 (y_t^k) 位于归一化动作空间或编码观察空间。其带噪版本为

\[
x_t^k=(1-s_k)y_t^k+s_k\epsilon_k,qquad
\epsilon_k\sim\mathcal N(0,I),
\]

其中 (s_k\in[0,1]) 从基础噪声调度中采样。当前观察 (o_t)、指令 (g) 和轨迹 (r_t) 保持不加噪。收集带噪目标和噪声水平为 (x_t) 与 (s)，我们最小化

\[
\mathcal L_{\mathrm{pred}}
=\mathbb E\left[\sum_{k\in K}\alpha_k
\operatorname{MSE}_k\left(v_\theta(x_t,s\mid o_t,g,r_t),\epsilon-y_t\right)\right].
\tag{1}
\]

这里 (v_\theta^k) 是模型参数预测的速度，期望覆盖示范、噪声和噪声水平。模态权重 \(\alpha_k\)，以及 \(\operatorname{MSE}_k\) 中的 mask、时间加权和归一化，都遵循基础模型配方。

### VLA 实现

我们使用 π0.5-DROID：其 PaliGemma 主干由 SigLIP 视觉编码器和 Gemma 语言模型组成，另有一个 3 亿参数的动作专家。两层编码器把 PaliGemma 的轨迹 embedding 映射成 token，并追加到图像与指令上下文之后。轨迹关注该上下文，动作专家同时关注上下文和轨迹；所有组件联合微调。此时 \(y_t^{\mathrm{act}}=a_t\) 是示范动作块。

仅使用事实监督时，对于相同观察配上相互冲突的轨迹，模型预测几乎不变。为了抑制这种捷径，我们把约 5% 的轨迹替换为与示范动作相矛盾的反事实轨迹 \(r_t^-\)，并从 \(\mathcal L_{\mathrm{pred}}\) 中排除这些样本。令 (s_{\mathrm{act}}=1)，并写

\[
\hat a_t^- = \epsilon-v_\theta^{\mathrm{act}}(\epsilon,1\mid o_t,g,r_t^-),
\]

我们惩罚它靠近示范动作：

\[
\mathcal L_{\mathrm{cf}}
=\mathbb E\left[\max\left(0,m-operatorname{MAE}_{\mathrm{real}}(\hat a_t^-,a_t)\right)^2\right],
\qquad
\mathcal L_{\mathrm{VLA}}=\mathcal L_{\mathrm{pred}}+\lambda_{\mathrm{cf}}\mathcal L_{\mathrm{cf}}.
\tag{2}
\]

\(\mathcal L_{\mathrm{cf}}\) 的期望覆盖反事实样本和动作噪声；\(\mathcal L_{\mathrm{pred}}\) 只使用事实样本。边界 (m>0) 位于归一化动作空间，\(\lambda_{\mathrm{cf}}) 对惩罚加权，\(\operatorname{MAE}_{\mathrm{real}}) 在时间范围和 8 个非 padding 动作坐标上取平均。这样无需额外的替代动作示范，就能提供负向监督。实现细节见附录 B.1。

### WAM 实现

Cosmos3-Nano-Policy 将视觉-语言推理器和扩散生成器结合起来，两者通过每一层的注意力连接，但参数分离。生成器关注两组 token；推理器只关注自己的 token，因此无需修改架构就能加入轨迹条件。每个窗口包含一帧观察，以及带动作的 32 帧未来画面，并与第一帧的轨迹配对。我们联合微调两个组件：

\[
\mathcal L_{\mathrm{WAM}}=\mathcal L_{\mathrm{pred}}+\lambda_{\mathrm{trace}}\mathcal L_{\mathrm{trace}},
\]

\[
\mathcal L_{\mathrm{trace}}
=-\mathbb E\left[\sum_{j=1}^{|r_t|}
\log q_\phi(r_{t,j}\mid o_t,g,r_{t,<j})\right].
\tag{3}
\]

其中 (q_\phi) 是推理器的下一 token 分布，\(|r_t|) 是轨迹长度，\(r_{t,j}) 与 \(r_{t,<j}\) 分别表示第 (j) 个 token 及其前缀。系数 \(\lambda_{\mathrm{trace}}\) 对轨迹监督加权，期望在已标注窗口上计算。生成器使用真实轨迹作为条件，而预测损失的梯度也会更新推理器。由于 Cosmos3 的推理器更大（8B，而 π0.5 为 2B），在冲突轨迹下它已经会产生不同的动作分布；加入 \(\mathcal L_{\mathrm{cf}}\) 没有可测量收益，因此省略。

### 推理

推理时冻结经过 ARC 微调的模型，并使用外部 VLM 根据任务指令和当前相机观察生成推理轨迹；执行过程中按选定频率刷新轨迹。VLA 的视觉-语言主干和 WAM 的推理器分别把轨迹编码为条件表示，用来控制动作专家和生成器。之所以使用外部生成，是因为模型内置语言组件在生成这些轨迹方面不如在利用轨迹控制方面可靠（见第 5.2 节）。在评估的外部 VLM 之间，ARC 的任务性能基本相当。由于轨迹是自然语言，其生成可以直接受益于标准 LLM 推理优化。附录 B.3 和 B.3.1 介绍刷新计划和服务优化，包括一个只增加约 10 ms 控制循环开销的近实时 VLA 部署。

## 5.2 主要发现与消融实验

表 1、表 2 和表 3 支持本文的核心发现：更强的因果语言接地会带来更强的整体性能。这种提升同时出现在两类模型上。ARC 可以把相对较弱的 π0.5 提升到未修改 WAM 基线之上，也能显著改进已经很强的 Cosmos3-Nano-Policy。收益不仅体现在成功率，还体现在鲁棒性和效率上。我们总结四项主要发现。

### KF#1：推理改善长时程、动态和推理密集型任务的执行

在长时程任务中，ARC 会跟踪进度并保持剩余步骤的顺序。当执行期间场景发生变化时，更新后的推理会把机器人重新导向当前需要处理的对象。推理密集型任务还要求机器人发现指令中没有明确说明的前置条件，并采取完成任务所需的中间步骤。这些行为伴随更强的错误恢复：动作失败后，机器人会尝试修正。

我们的解释是，明确把当前状态与预期效果连接起来，可以通过同一种表示支持多种决策：动作排序、发现必要步骤、响应变化和修正错误。

图 5 给出动态环境示例：人类在任务执行中添加或移除物体。若机器人最初把橙子移向错误的碗，在线推理会重新判断“橙子属于黑碗”，并在释放前将其转向正确目标。

### KF#2：性能几乎不受指令具体程度影响

在 RoboLab-120 上，使用 ARC 微调的策略在模糊、默认和具体三种指令下保持相近的成功率，而基础策略随着指令变得不明确会明显退化。推理会结合场景解释指令，并识别下一动作应实现的效果，因此即使原始指令没有提供很多细节，控制器也能得到更具体的目标。换言之，用户需要提供的细节变少了。

### KF#3：推理带来推理时加速

在 RoboLab-120 上，π0.5 + ARC 用单个 Euler 步就能达到基础策略十步的性能，推理步数减少 10 倍；Cosmos3-Nano + ARC 用两个 UniPC 步达到基础策略四步的性能，推理步数减少 2 倍。我们的假设是，明确说明预期效果会缩小可能动作集合，减少多模态性，简化模型需要整合的 flow。既然更多决策已经在推理阶段解决，较粗的积分就足够了。Cosmos3-Nano 在一步时仍会损失性能，这与 UniPC 需要多步历史才能进行高阶修正相一致。

### KF#4：更少的训练更新即可达到目标性能

在 Cosmos3-Nano-Policy 上，ARC 约用 4.3 倍更少的更新就达到指令-only 基线在 1 万次迭代时的性能，并且继续训练仍会提升。我们的解释是，因果监督使每条示范包含更多信息：模型不仅看到观察—动作对应关系，还得到示范动作的原因，因此不必仅靠重复观察—动作样本来推断原因。推理提高了训练产生有效行为的效率，也提高了最终策略性能。

### 关键消融实验

**AB#1：改变外部 VLM。** 固定经过 ARC 微调的 π0.5 检查点，只改变外部 VLM。不同 VLM 的性能相近，说明 ARC 不依赖某个特定轨迹生成器。

**AB#2：分别去掉轨迹成分。** 结果指出轨迹有两个互补作用：因果说明确定哪个状态变化重要以及为什么重要；动作含义把这个变化连接到具体物理步骤。没有动作含义，控制器必须自己推断如何实现预期效果；只有动作含义，则得到一个缺乏因果上下文的命令。禁止效果会约束行为，但本身不指定应执行什么，因此单独使用时不一定有效，放在完整因果说明中才有帮助。

**AB#3：全量微调与只训练动作头/生成器。** 预训练语言特征并不会自动以控制器可直接利用的形式暴露因果区别。只训练动作头会固定这些特征，让控制器必须从固定表示中恢复相关区别。全量微调则允许预测误差重新塑造特征，使主干学会区分那些因条件和预期效果不同而需要不同动作的情况。

外部 VLM 消融的成功率约为：GPT-5.5 45.6%，Qwen3.6-35B-A3B 45.3%，MiniMax-M3 45.0%，Gemini 3.6 Flash 44.4%，Cosmos3-Nano-Reasoner 40.4%，基础 π0.5 28.0%。

完整六个轨迹成分时成功率为 45.3%；去掉 State 为 37.17%，去掉 Cause & Effect 为 39.25%，去掉 Action 为 30.58%，去掉 Avoid 为 35.83%，去掉 Completion 为 42.33%，只保留 Action 为 27.42%，State + Action 为 32.25%，State + Action + Avoid 为 26.75%，无轨迹基线为 28.0%。

在 π0.5 上，全量微调达到 45.0%，只微调动作头为 30.9%，基础模型为 28.0%。在 Cosmos3-Nano-Policy 上，全量微调达到 51.2%，只微调生成器为 43.7%，基础模型为 39.0%。

# 6 结论

本文提出 ARC，一种在不收集新的机器人示范、不重复基础模型规模训练的情况下，显著提升预训练 RFM 零样本任务执行能力的推理配方。将 ARC 应用于 π0.5 和 Cosmos3-Nano-Policy 后，我们在 RoboLab-120 和 MolmoSpaces 上建立了新的最佳水平，提升了对含糊和信息不完整指令的鲁棒性，并提高了训练和推理效率。

有前景的后续方向包括：让策略可靠地自行生成因果轨迹，以及把该配方扩展到更多机器人形态。简单地说，RFM 不需要被重新构建才能推理。以动作和因果关系为基础的语言，是一种成本低而收益高的扩展方向。

# A ARC-TRACE 与 ARC-TRACE-DROID 细节

## A.1 ARC-Trace 数据标注细节

ARC-Trace 由三个阶段构成，如图 3 所示。Gemini 2.5 Pro 解读 episode 视频并选择重要帧；GPT-5.5 随后生成 episode 专属的状态检查，并结合这些证据、任务、episode 叙述和选定观察，生成动作基础的因果轨迹。将 episode 级解读与帧级标注分开，可以为每条轨迹提供解释当前决策所需的上下文。

### 源数据与覆盖范围

我们使用 DROID v1.0.1 的训练划分，其中包含 95,658 个 RLDS/TFDS 格式的 episode。示范以 15 Hz 记录，包括腕部相机和两个外部相机视图、机器人状态、动作以及任务指令。标注运行覆盖约 74,740 个 episode，即源训练划分的 78.1%，产生约 120 万个标注帧，平均每个已标注 episode 约 16.1 条标注。大多数没有标注的 episode 缺少可用任务指令；处理失败会单独记录。

### Episode 叙述与关键帧选择

Gemini 2.5 Pro 接收任务指令和 episode 视频，生成在时间上对齐的示范叙述。叙述描述涉及的物体、机器人的动作以及场景中产生的变化。episode 级描述为单张图像无法提供的内容提供上下文，包括任务哪些部分已经完成。同一视频标注阶段还会选择重要帧。选择由 VLM 对示范的解读指导，而不是采用固定的均匀采样间隔。每个选定帧都会映射回原始帧索引 (f) 和时间戳 (f/15)。

### Episode 专属谓词生成

对选定观察，GPT-5.5 生成描述与任务相关的物体、关系和条件的状态检查。本阶段采用低推理强度设置。图 3 的示例中，检查包括 `target_object`、`target_container`、`pot_visible` 和 `gripper_open`。它们确定指令中提到的对象和目的地，并在组合最终轨迹之前明确相关视觉条件。这些输出为轨迹标注器提供结构化证据，减少其仅凭图像和叙述重建任务状态的需要。谓词是模型生成的视觉证据描述，并非独立测量得到的真实状态。

### 动作基础轨迹生成

GPT-5.5 再次使用低推理强度，把任务指令、episode 叙述、选定腕部观察和状态检查输出组合成结构化推理标注。标注包含第 4.1 节定义的七个语义字段，把感知状态和相关原因连接到可能后果、选定效果、动作含义、禁止效果和完成状态。每条记录包含一个 `natural_language_construction`，即由 3–6 句话组成、目标长度约 700 个字符的流畅段落。该段落把因果说明与相关物体和抓取信息结合起来。结构化字段便于检查和表示消融；段落则是策略条件化时实际使用的自然语言推理。

### 时间对齐与保存的工件

每条标注保留 episode 索引、关键帧标识符、原始帧索引和时间戳。episode 索引指向 RLDS 训练划分中的源记录，帧索引指向对应观察以及相关动作块的起始位置。这保持了与原始示范的对齐，不修改观察和动作。每个 episode 保存一个 JSON 记录，标注按时间顺序排列。选定图像、episode 视频、原始模型响应、解析后的输出、模型标识符和提示词版本都会与标签一起保留。完整 episode 视频只在离线构建监督时使用，不会作为部署策略的额外输入。

# B 微调与推理配方细节

## B.1 VLA 微调细节

### 观察与指令编码

图 12 展示 π0.5-DROID 实现。(o_t) 中的外部相机和腕部相机图像被调整为 (224\times224)，由 SigLIP 编码为每个视图 256 个 token。这些 token 被投影到 Gemma 主干的 2048 宽度。任务指令 (g) 和离散化机器人状态通过 PaliGemma tokenizer 一起编码，最大长度为 200 token。图像和指令 token 构成原始上下文；未使用的相机槽位和 padding 会被 mask。

### 轨迹编码

轨迹 (r_t) 单独进行 token 化，最大长度为 320 token，并使用同一个 PaliGemma embedding 表进行嵌入。轨迹编码器把 2048 维 embedding 投影到宽度 512，加入学习到的位置 embedding，并应用两个预归一化 Transformer 块。每个块有 8 个注意力头，前馈宽度为 2048。最终投影把表示恢复到宽度 2048，再追加到上下文中。这个投影被零初始化，因此训练初始时新表示不携带轨迹特有的信息。

### 逐层条件化

上下文和轨迹 token 由 Gemma-2B 参数处理；带噪动作 token 由 3 亿参数动作专家处理。两个组件宽度分别为 2048 和 1024，并在 18 个 Transformer 层中的每一层通过共享注意力交互。尽管隐藏宽度不同，注意力投影仍会产生兼容的 key、query 和 value。

块 mask 的规则是：上下文 token 可以彼此全注意；轨迹 token 可以关注上下文和轨迹；动作 token 可以关注上下文、轨迹和动作。换言之，轨迹可以使用观察场景和指令，动作专家可以把二者与带噪动作块结合起来；上下文和轨迹表示不依赖带噪动作。虽然输入序列中轨迹 token 位于动作 token 之前，但其旋转位置索引被分配到动作位置之后，从而保留预训练动作 token 的位置索引。

### 动作预测与训练

动作块长度为 (H=15)，归一化动作目标为

\[
y_t^{\mathrm{act}}=a_t\in\mathbb R^{H\times32}.
\]

其中 8 个坐标表示 7 个关节和夹爪，其余坐标是 padding。(x_t^{\mathrm{act}}) 的每一行被投影为一个 1024 维动作 token。对 (s^{\mathrm{act}}) 做正弦嵌入后再经过 MLP，通过自适应 RMS 归一化条件化动作专家。最终 token 表示被投影回 32 个坐标，产生 (v_\theta^{\mathrm{act}})。视觉编码器、语言主干、轨迹编码器和动作专家共同使用式（2）优化。

事实样本和反事实样本共享一次批量前向传播；损失 mask 分别选择 flow matching 损失或反事实惩罚，反事实样本设 (s^{\mathrm{act}}=1)。flow 损失使用带 padding 的动作表示，而计算反事实距离的 MAE 会排除 padding。

## B.2 WAM 微调细节

### Token 构造

如图 13 所示，Cosmos3-Nano-Policy 的推理器接收当前观察的 ViT 编码、任务指令 (g) 和轨迹 (r_t)，使用预训练语言 tokenizer 和 embedding。轨迹直接追加在指令之后，不使用单独的轨迹编码器。序列边界由结束序列 token（EOS）和生成开始 token（BOG）标记。

生成器处理连续的观察和动作表示。每个训练窗口含一帧观察，以及与动作对齐的 32 帧未来观察。视频 VAE 把未来观察编码为 (y_t^{\mathrm{obs}})，归一化动作形成 (y_t^{\mathrm{act}})。它们的带噪版本 (x_t^{\mathrm{obs}}) 和 (x_t^{\mathrm{act}}) 被投影为生成器 token。基础 Cosmos 视频输入还保留初始帧作为干净的 VAE 条件，与加噪的未来目标分开。

### 推理器—生成器注意力

Cosmos3-Nano 使用 36 个配对 Transformer 层，宽度为 4096。推理器和生成器具有分离的归一化层、注意力投影和前馈网络，但 token 通过共享注意力操作交互。因果注意力限制每个推理器 token 只能关注前面的上下文和自身。生成器 token 可以关注完整推理器序列以及其他生成器 token，使动作和未来观察预测能够交换信息，同时保持轨迹条件。独立输出投影分别在各自目标空间产生 (v_\theta^{\mathrm{act}}) 和 (v_\theta^{\mathrm{obs}})。

### 联合监督

训练时，真实轨迹有两个作用：为生成器提供条件，同时为推理器提供下一 token 目标。对于 \(\mathcal L_{\mathrm{trace}}\)，目标向右移动，因此预测 (r_{t,j}) 时只能使用 (o_t)、(g) 和 (r_{t,<j})。推理器不能关注后面的轨迹 token 或扩散目标。但生成器在预测动作和未来观察时，会以完整真实轨迹为条件。

我们依据式（3）联合更新两个组件。轨迹损失监督推理器的语言预测；\(\mathcal L_{\mathrm{pred}}\) 也会通过生成器使用的 key 和 value 更新其表示。因此，推理器同时学习表达标注推理和提供连续预测所需的特征。反事实目标按第 4.3 节所述省略。

## B.3 推理

评估期间冻结 ARC 微调后的策略，并使用外部 VLM 生成动作基础的因果轨迹。每次请求包含任务指令、当前外部相机图像和腕部相机图像。固定提示词规定 ARC 轨迹格式，并要求输出一个基于当前观察、最多 900 个字符的自然语言段落。

生成的轨迹会与原始指令和观察一起提供给策略。对 VLA，视觉-语言主干为动作专家编码轨迹；对 WAM，推理器为生成器编码轨迹。外部 VLM 负责推理，ARC 微调后的策略负责生成连续机器人动作。响应在使用前会检查格式和长度；被拒绝的响应不会替换上一次已经接受的轨迹。轨迹生成异步运行，每次策略调用使用最近一次接受的轨迹。

## B.3.1 实时部署

我们把推理生成与动作执行分开，使机器人无需在每次策略查询时等待新轨迹。机器人以 15 Hz 执行长度为 15 的动作块，后台线程根据最新相机观察生成推理。episode 初始化后，每次策略查询使用最近验证过的轨迹；延迟或无效响应会保留上一条轨迹。因此，推理延迟只会影响场景解释的新鲜程度，不会阻塞后续动作生成。

为了在一个动作块持续时间内刷新推理，我们在专用 GPU 主机上使用 vLLM 本地服务 Qwen3.6-35B-A3B-FP8。本地服务避免远程 API 延迟；FP8 推理和前缀缓存降低计算与内存成本。共享系统提示词和任务指令位于图像之前，使其缓存表示能够在请求之间复用。我们关闭额外思考 token 的生成，只要求一个最多 900 字符的因果段落。每个请求包含两张相机图像，并通过限制并发量来控制排队。

## C.3 评估策略

### π0.5

我们使用公开的 π0.5-DROID joint-position 检查点。其 PaliGemma 主干把 SigLIP 视觉编码器与 Gemma 语言模型结合起来，用于处理相机观察、任务指令和 token 化的机器人状态。一个独立的 3 亿参数动作专家关注这些表示，并通过 flow matching 预测连续动作块。基础策略只接收原始任务指令，不提供额外推理；动作生成使用默认的 10 个 Euler 步。

### Cosmos3-Nano-Policy

我们使用 Cosmos3-Nano-Policy 的 DROID 检查点。这是一个基于混合 Transformer（mixture-of-transformers）的世界动作模型，将视觉-语言推理器与扩散生成器结合起来，两者参数分离并在每层通过注意力连接。推理器处理视觉和语言输入，生成器根据推理器表示联合预测未来观察和动作。详细架构和预训练说明请参阅原论文。

### 带显式子任务的 π0.5

该基线评估不修改、不微调策略时的外部任务分解能力。我们保留原始 π0.5-DROID 检查点，用 GPT-5.5 根据任务指令和初始外部相机图像生成有序计划。计划最多包含 12 个粗粒度子任务；完整的抓取—放置操作视为一个子任务。对于多物体指令，规划器明确列出匹配物体，并排除指令排除的物体。单物体指令和发现指令在这种粗粒度分解下保持原样。

执行时，客户端包装器把原始指令替换成当前子任务，而观察、机器人状态和策略保持不变。客户端每次策略查询执行 15 个动作。每 30 个仿真步，GPT-5.5 根据外部和腕部相机图像检查当前子任务。只有当物体到达目的地、已经释放并且保持稳定时才算完成；连续两次正向检查会推进计划。如果分配给子任务的步数预算耗尽，子任务也会推进；每个子任务至少分配 225 步，episode 总预算按子任务划分。失败的子任务会被跳过而不重试，最后一个子任务保持激活直到 episode 结束。

规划器和完成检查器使用低推理强度、温度 0.2。计划每个 episode 只生成一次，不重新规划；空计划或无效计划会退回原始指令。外部 VLM 只提供子任务提示和完成判断，所有机器人动作仍由 π0.5 负责。

## 任务：反转排列

任务是“盘子里的所有东西放入碗中，碗里的所有东西放到盘子上”。轨迹依次说明：香蕉必须先离开碗，暂时放到桌面为盘子腾出空间；碗已经清空，抓起盘子上的标记笔并稳妥移入碗；木块仍在盘子上，安全抓取后放入碗；红块是盘子上最后的物体，把它移入碗以清空盘子；盘子原本的内容现在都在碗中，把香蕉从桌面放回已经清空的盘子。

# F ARC 的局限性

## 对推理质量的依赖

ARC 依赖 VLM 生成忠实的推理。如果推理器误解任务或提出不合适的动作，更强的语言接地可能把错误带入执行。评估中的不同 VLM 表现相近，并不意味着 ARC 对任意推理错误都鲁棒。更强或经过任务适配的推理器可能提升可靠性；同时还可以加入检查，使轨迹不仅通过格式验证，还要与观察相符。

## 遮挡与观察不完整

即使推理器能力很强，当物体或夹爪遮挡关键信息时，也可能误判场景。尤其是，抓取或放置状态不确定时，模型可能把某一步误认为已经完成，导致后续推理基于错误的任务状态继续进行。更短的观察历史和更清晰的相机视角可能有助于解决这些歧义。显式表示不确定性，并在做下一步决定前请求再次观察，也是值得研究的方向。

## 推理开销

外部推理会增加计算、内存使用和延迟；仅减少去噪步数无法消除这些开销。本文的本地异步部署减少了等待，但在新推理生成期间，策略可能继续使用过时轨迹。当场景快速变化时，这种权衡尤其重要。把轨迹生成蒸馏到更小的模型中，并只在任务相关变化发生后选择性刷新轨迹，可以降低成本；检查轨迹的新鲜度则可以减少对过时推理的依赖。

## G.1 视频标注

系统消息和用户消息根据腕部相机视频描述可见的执行过程。当同时请求叙述和关键帧时，会追加额外要求；输出变为 JSON，但仍保留密集时间线和细节审计。

### 系统提示词

你直接观看机器人操作视频，并写出精确、高保真的自然语言叙述。不要把视频压缩成泛化的任务脚本。保留细小的物理细节：抬起前的运动、拖动、滑动、物体取出、接触变化、失败尝试、修正、释放、碰撞、遮挡和最终状态。除非明确要求，否则不要返回 JSON。

### 用户提示词

直接观看完整的机器人示范视频，并写出发生了什么的高保真自由叙述。

- Episode：`{episode_index}`
- 指令：`{instruction}`
- 相机：`observation.images.wrist_image_left`
- 视频上下文：只提供腕部相机视频。该相机会随机器人夹爪移动，因此应优先关注近距离夹爪接触、手指张合、抓取、拖动、抬起、释放和局部物体运动。当腕部视角无法显示环境布局、目标容器状态或最终放置时，应把这些信息标为不确定。

**数据集和机器人上下文：** 该示范来自 DROID 机器人操作数据集。视频展示真实机械臂操作日常桌面物体。末端执行器是腕部安装的平行双指夹爪：两根相对手指可以张开、闭合、夹取、按压、钩取、拖动或携带物体。腕部相机随夹爪移动，通常提供近距离但局部的接触视图；外部相机提供关于物体位置、表面、容器和最终放置的更宽上下文。

你的目标不是总结任务，而是重建视频中可见的物理执行过程。不要假设机器人执行了指令暗示的标准计划；描述视频中实际发生的内容，包括笨拙、部分完成、低效或修正动作。

**必须遵守的输出样式：**

- 使用包含许多小步骤的密集编号时间线，不要只写一段简短摘要。
- 末尾加入简短的“细节审计”，列出容易遗漏的小型物理运动，特别是干净抬起或搬运之前的物体运动。
- 只使用自然语言，不要输出 JSON。

**必须遵守的粒度规则：**

- 只要机器人方向、夹爪张合状态、末端执行器接触、物体接触、物体运动、操作模式、目标关系或可见性发生变化，就拆分时间线。
- 在说物体被拾起、抬起、携带或放置之前，先描述抬起前的接触阶段：夹爪如何靠近、碰到了什么、物体是否仍在支撑面上运动，以及物体是否从邻近物体或边缘处被拉出、滑出或拖出。
- 只有当物体明显离开支撑面、下方出现空气时，才写“干净地拾起”“抬起”或“携带”。如果物体仍与桌面、托盘、容器、另一个物体或边缘接触，应使用“滑动、拖动、刮擦、轻推、推动、拉动、旋转、分离、取出或重新定位”等物理动词。
- 如果动作有两个阶段，分别写出两个阶段，例如先接触/拖动/取出，再抬起/携带；或先推动/轻推，再释放/稳定。
- 区分稳定抓取、部分接触、夹取、钩取、按压、侧面碰撞、用夹爪拖动等状态。
- 跟踪被操作物体在到达最终状态前的完整路径：初始位置、第一次移动、表面接触运动、可见的离面、搬运、对齐、下降、释放、释放后的调整和最终静止姿态。
- 提及与其他物体、支撑面、托盘/容器边缘、固定装置或目标区域的偶然或非预期接触。
- 提及所有失败或部分尝试：抓空、抓取不牢、滑落、重新抓取、再次接近、超过/未达到目标、停顿、犹豫、修正、重复对齐或释放后物体稳定过程。
- 明确标注不确定性。如果接触、离面、释放或最终关系被遮挡或难以看清，应说难以判断，不要把它润色成干净动作。
- 不要写过于干净的叙述。机器人示范常常包含细小的预抓取或预抬起表面接触运动；在描述抬起或搬运前，主动检查初次接触期间是否有取出、拖动、滑动或旋转。
- 如果视频既可能支持干净抬起，也可能支持短暂拖动/滑动，应采用谨慎措辞：“物体似乎被接触到，并可能在离面前短暂滑动/拖动”，而不要断言干净抬起。

**回答前自检：** 是否跳过了离面前的物体运动？是否把拖动、滑动或推动写成了干净抓取？是否遗漏轻推、修正或释放后的调整？机器人是否沿表面移动物体后才搬运？是否把夹爪接触误认为稳定抓取？

不要编造视频中不可见的细节。除非整个接触阶段在多个时刻都清晰可见，否则不要做“没有拖动”或“干净抬起”之类的自信否定；如果接触阶段很短、部分遮挡或有歧义，应写明抬起前运动不确定，并描述可能的表面接触运动。

### 额外要求：叙述 + 关键帧

本次同时返回叙述和选定关键帧时，只返回 JSON。叙述仍必须是密集编号时间线，并包含细节审计。还要从同一段腕部相机视频中选择关键帧。

## G.3 推理时推理器提示词

### 推理时系统提示词

你是一个机器人操作系统的推理模块。一只带双指平行夹爪的机械臂在桌面上工作，由外部场景相机和安装在机器人腕部的相机观察。每次调用都会收到任务指令和两张当前相机帧，第一张来自外部相机，第二张来自腕部相机。你的完整回复必须是一段普通英文 prose；一个小型动作策略会读取这段话来决定机器人下一步动作。它是你与机器人的唯一通道，不会被人阅读，因此每句话都必须包含有依据的、物理上可执行的内容。

**输出格式硬规则：** 违反规则的段落会被拒绝，机器人继续使用上一条过时段落，因此必须严格遵守。只返回段落本身：不得有 JSON、Markdown、代码围栏、列表、标题、包围段落的引号、前言、结束语或任何前后附加内容。整段只能是一行，句子之间用单个空格分隔，不能有换行或制表符。写 4–7 句话，总长度少于 900 个字符。不要写任何形如“单词:”的标签，也不要使用冒号，必须写成自然连贯的段落。不得出现数字或数值、计数、单位、角度；距离、高度和大小都用定性表达，例如“略偏左”“就在边缘上方”“几乎接触表面”“与边缘保持足够距离”。不得提及相机、图像、帧、视图、屏幕、面板、布局、像素、坐标、模型、策略或这些指令；你是通过机器人的相机看世界，因此只谈世界。左和右始终指工作空间中的物理方向，以物体和桌面为参照，而不是图像区域。

**内容要求：** 段落按六个动作自然展开，不能使用标签。

1. **感知状态**：以“The robot sees”开头，描述当前重要物体，按颜色和种类命名，说明它们相对于彼此、工作表面和夹爪的位置；明确夹爪所在位置、手指张开或闭合，以及是否夹着物体。
2. **相关原因**：说明决定下一步的物理事实，例如物体仍在容器内，所以必须先稳定抓取再抬出。
3. **选择的效果**：用“The chosen effect is”开头，说明下一步运动希望产生的物理结果，例如对暴露物体形成稳定、居中的抓取。
4. **动作含义**：用“This implies the robot should”开头，给出具体运动、移动方向、对齐方式、下降时机以及手指保持张开还是闭合。
5. **禁止效果**：用“The robot must not”开头，指出当前场景中最重要的具体风险，例如撞倒容器、把持有物体拖过另一个物体、碰撞边缘或悬空时释放；不要使用泛泛的占位语句。
6. **完成状态**：以“The task is incomplete, since ...”或“The task is complete, since ...”结尾，并给出可见证据。

**重新判断场景，不要假设。** 机器人执行动作后，两次观察之间可能已经完成多步动作；上一条推理很可能已过时，只能作为上下文，不能作为证据。每次写作前都要从当前两张图像重新确定：任务物体现在在哪里，是在桌面上、容器内、闭合手指之间，还是已经在目标处；夹爪在哪里、手指张开还是闭合；这些事实对应任务的哪个阶段。若物体已经被夹住，接近阶段就已经结束，不要再次指示机器人去够取、对齐或下降；应继续抬起和搬运。若物体已经在目标处且手指已张开并离开，应说任务完成，不要重新开始。让机器人重复已经完成的阶段会主动破坏任务，因此每次必须相信当前图像。

**相机角色。** 两个视角回答不同问题，必须同时使用。外部视角是距离判断的依据：它从侧面看到夹爪和物体，只有它能显示指尖距离物体有多远；如果外部视角显示指尖与物体之间有空气，无论腕部视角中物体看起来多居中，夹爪都还没有到位。腕部视角是居中和确认完成抓取的依据，因为它沿手指方向观察，能显示物体是否位于两指之间；但它不能判断距离，因为远处和近处的物体看起来可能几乎一样，因此不能仅凭腕部视角推断接近程度。

**验证，不要假设。** 只有当物体明显位于闭合手指之间，或清楚地悬挂在闭合夹爪上时，才能认为物体被抓住。如果手指只是闭合在空气中，或物体仍在原处，就不能认为已经抓住；应明确说出这一点并据此指导动作。把图像没有清楚显示的抓取或进展说成事实，是最严重的错误。手指刚闭合后，下一段推理应进行验证：若物体确实被抓住，就进入抬起和搬运阶段，并保持手指闭合；若没有抓住，通常是手指闭合得太高，新的接近动作应让手指明显更深地来到物体两侧、低于上次闭合位置，然后再次闭合。

**恢复只向前看。** 不要叙述或解释过去的失败、滑落、掉落或早先尝试；只描述当前场景和下一步动作。如果被抓物体掉落，段落只需描述物体现在停在哪里、需要重新抓取，以及新的接近过程。如果夹爪悬停在错误物体附近，应说明错误物体在手指下方，而真正目标在其他位置，并让夹爪张开、向上并横向移动到真正物体处。

**完成纪律。** 只有当当前图像中清楚满足目标条件、物体已在目标处稳定放置且手指张开并离开时，才宣布完成。一旦完成，选择的效果是保持一切原样，动作含义是让张开的夹爪轻柔向上撤回，禁止效果是扰动已经放置的物体或周围环境。

### 响应接受规则

空白规范化后，验证器检查：

- 以四种允许的开头之一开始：`The robot sees`、`The robot currently sees`、`The robot observes` 或 `The robot detects`；
- 长度为 150–950 个字符，句子数为 3–8；
- 不含数字和形如“Word:”的标签；
- 包含 `must not`，并且包含 `task is complete` 或 `task is incomplete`。

这些接受检查与生成指令不同：系统提示词要求固定开头 `The robot sees`、4–7 句话、少于 900 个字符，并要求满足额外内容和格式规则。

- **RFM**：Robot Foundation Model，机器人基础模型。

- **WAM**：World Action Model，世界动作模型。
